# GEO Intelligence P0 V1.44 增量记录

> 状态：已记录｜日期：2026-11-14｜前置基线：V1.43，待项目负责人确认

## FEAT-08 批量复核与仲裁回写

- 新增批量端点（单次最多 100 项，逐项独立事务，单项失败不回滚整批）：
  - `POST /review-queue/batch-annotations`；
  - `POST /review-queue/batch-adjudications`；
  - `POST /review-queue/batch-assignments`。
- 响应统一为 `{applied, failed, results[]}`，失败项带 `NOT_FOUND` / `NOT_PENDING` / `INVALID_INPUT` / `INTERNAL` 错误码。
- 仲裁结果回写 `answer_evaluations`：
  - 新增 `human_decision_json`、`human_adjudication_id`、`human_reviewed_at`（迁移 `000021_review_writeback`）；
  - 只接受受控字段 `answerOutcome` / `recommendationLabel` / `contentValidity` / `sentiment` / `eligible`，枚举非法返回 422；
  - 未知字段保留在仲裁记录中，但不参与回写。
- 新增 `POST /audits/{auditId}/metrics/recompute`：
  - 基于回写后的有效判定重建 `metrics-v1h` 快照；
  - Judge 原始 `metrics-v1` 快照保持不可变，报告冻结的指标不受影响；
  - 重复重算按“清空并重建”幂等处理。
- 复核页面新增全选/多选、批量复核、批量仲裁、批量分派，以及“按仲裁结果重算该审计指标”入口。

## FEAT-04 正文候选与快照对比

- 新增正文候选抽取 `text-v1`：
  - 英文与中文定义句式（`X is a …` / `X 是一个…`）解析为带类型的候选实体；
  - 类型映射到 `Organization` / `SoftwareApplication` / `Product`，无法归类则不产生候选；
  - 每页最多 5 个候选，状态为 `proposed`，附原文引用与 `text:def` 定位；
  - 已确认实体在正文中出现时补充 `page_text` 来源证据，不覆盖 JSON-LD 结果。
- 抓取落库时在 JSON-LD 抽取之后调用正文抽取，结构化数据仍是权威来源。
- 新增知识快照读取与对比：
  - `GET /projects/{id}/knowledge-snapshots` 按版本倒序列出快照；
  - `GET /projects/{id}/knowledge-snapshots/diff?from=&to=` 返回实体新增/移除/变更（状态、别名）与关系新增/移除；
  - 实体页面新增“知识快照对比”面板，可发布快照并查看两次快照差异。

## 实测

- 批量复核：3 项入队，批量标注 2/2 成功；重复标注返回 `NOT_PENDING`，整批仍返回 200。
- 批量仲裁：2/2 成功；重复仲裁返回 `NOT_PENDING`。
- 回写校验：`answerOutcome=recommendation, eligible=true` 与 `answerOutcome=refusal, eligible=false` 均落库，`human_adjudication_id` 非空。
- 非法枚举 `answerOutcome=definitely-not-an-outcome` 返回 422 `REVIEW_INPUT_INVALID`。
- 指标重算：返回 16 个指标，`mention_rate` 维度 `model_api` 为 1/1。
- 快照对比：v2 → v3 检出 1 个变更实体（`Acme GEO Inc`，`proposed` → `confirmed`）。
- 证据：`.run/feat08-feat04-verification.json`。

## 已知边界

- 正文候选只覆盖“定义句式”，不处理同义改写、列表页与表格；未做 Microdata 解析。
- 正文候选仅经单元测试验证，本次未跑真实网站抓取回归。
- 快照对比不做跨项目比较，也不回填快照之间的中间状态。
- 仲裁回写不修改 `evaluation_runs` 的 Judge 版本，重算结果以 `metrics-v1h` 区分。
- 批量分派需要调用方提供成员 ID，页面暂未提供成员下拉。
