# FEAT-07：Model Gateway 与预算

> 功能版本：V1.0｜产品版本：P0 V1.0｜状态：已批准  
> 需求：MOD-001、MOD-002、MOD-003、MOD-004、MOD-006｜对齐：SPEC-05、07、08 V1.0

## 1. 功能目标

以统一、可审计的方式接入多个模型供应商，标准化请求和响应，完整保存供应商原始结果，并实施模型目录、渠道隔离、限流、幂等、预算预留、成本结算和错误归一化。

## 2. P0 范围

- 至少两个模型供应商适配器。
- `model_api` 和正式支持时的 `search_api` 渠道。
- Engine Config、模型目录和能力声明。
- 同步供应商调用、平台内部异步执行。
- 组织月度、项目月度和单审计预算。
- 原始请求/响应、Usage、成本、延迟和错误保存。

消费者应用采集只有在获得合规授权和独立适配器后才启用，不能以普通 API 冒充。

## 3. 供应商适配接口

适配器实现：ValidateConfig、ListModels、Estimate、Execute、NormalizeResponse、NormalizeError、Reconcile。能力声明包括搜索、引用、地区、JSON 输出、流式和取消。

统一模型请求和响应遵循 SPEC-05；供应商特有字段保留在加密原始对象中，不污染上层业务契约。

## 4. 配置与密钥

- `engine_configs`：provider、channel、region、能力、限流、credential_ref 和状态。
- `model_catalog`：供应商模型、别名、能力、上下文限制和可用状态。
- `model_alias_versions`：别名到供应商模型的时间版本映射。
- 凭据进入 Secret Manager，数据库不保存明文。

测试连接使用最小请求，并显示脱敏错误。密钥创建、轮换和撤销写安全审计。

## 5. 预算模型

预算层级：组织月度 → 项目月度 → 单次审计 → 可选任务。所有金额使用整数微单位和 ISO 货币代码。

调用前：估算最大成本 → 原子预留 → 检查硬上限。调用后：按实际 Usage 结算 → 释放差额。Usage 缺失时使用保守上限并进入对账。

软阈值仅告警；硬阈值拒绝新调用。预算不能通过并发竞态超支，使用数据库条件更新或预算 Ledger 事务。

## 6. 数据模型

- `engine_configs`、`model_catalog`、`model_alias_versions`。
- `ai_requests`、`ai_responses`、`provider_attempts`。
- `budget_accounts`、`budget_reservations`、`cost_ledger`。
- `provider_health_events`、`rate_limit_states`。

请求以 `(tenant,engine,idempotency_key)` 唯一；相同键不同请求哈希返回冲突。

## 7. API

外部管理 API：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/api/v1/engine-configs` | 引擎配置 |
| POST | `/api/v1/engine-configs/{id}:test` | 测试连接 |
| GET | `/api/v1/model-catalog` | 模型和能力 |
| GET/PATCH | `/api/v1/projects/{id}/budgets` | 项目预算 |
| GET | `/api/v1/projects/{id}/costs` | 成本明细 |

内部 Gateway API 使用 `/internal/model-gateway/v1`，只接受服务身份。

## 8. 实现细节

1. Go Gateway 为薄层，不包含品牌判断、业务 Prompt 或指标逻辑。
2. 调用前解析模型别名并保存映射版本；响应保存供应商实际模型标识。
3. 供应商全局、凭据、租户和项目四级限流，租户之间采用公平调度。
4. 技术重试仅覆盖网络、408、429 和 5xx；认证、参数和政策错误不重试。
5. 外部结果未知时进入 Reconcile，不盲目重复可能收费的请求。
6. 原始响应先写 S3 并校验哈希，数据库成功引用后请求才算完成。
7. 原始和规范响应分开；规范化失败不删除原始结果，可重跑解析。
8. 日志记录 ID、长度、哈希、Usage 和错误码，不记录完整 Prompt、回答或密钥。
9. 不同渠道使用独立 Engine Config，任何聚合都必须携带 channel 维度。

## 9. UI

- 引擎配置页显示供应商、渠道、模型能力、健康状态和最近测试。
- 密钥输入后不再回显，只显示尾部指纹和更新时间。
- 预算页显示限额、已预留、已结算、剩余和预测。
- 审计启动前显示按供应商/模型的成本估算。
- 成本明细可下钻到 Audit 和 Sample，但无权用户看不到 Prompt/回答。

## 10. 异常与边界

- 供应商返回未知模型：保存原值并标记版本不透明。
- Usage 缺失：按保守价格结算并等待对账。
- 汇率问题：P0 不跨币种隐式换算；按原币种分别管理或使用明确价格表版本。
- 原始对象保存失败：任务重试，不能仅保存规范文本。
- 预算预留成功但任务取消：未调用部分立即释放，已调用部分结算。

## 11. 验收标准

- AC-01：至少两个供应商通过统一接口运行，相同业务层无需供应商分支。
- AC-02：每次调用保存实际参数、模型标识、渠道、地区、语言、时间、延迟、Usage、成本和原始响应。
- AC-03：相同幂等键重试不产生重复供应商调用或重复结算。
- AC-04：429/5xx/超时按策略退避，认证和参数错误不重试。
- AC-05：模型 API 与搜索渠道在配置、数据和成本中完全隔离。
- AC-06：启动前给出估算；达到硬预算后没有新调用发送，且并发下不会超出允许误差。
- AC-07：供应商成功但本地超时的故障注入进入对账，不盲目二次调用。
- AC-08：数据库、日志和错误响应中不存在明文密钥。
