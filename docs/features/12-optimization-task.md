# FEAT-12：优化任务管理

> 功能版本：V1.0｜产品版本：P0 V1.0｜状态：已批准  
> 需求：TSK-001～TSK-002｜对齐：SPEC-03、07、08 V1.0

## 1. 功能目标

把技术、实体、内容和 AI 回答中的 Finding 转换为具有证据、负责人、截止时间和验收条件的优化任务，并通过严格状态机管理人工执行和审核。P0 不自动修改或发布生产内容。

## 2. 用户故事

- 分析师从报告中的 Finding 创建任务，证据自动关联。
- 项目管理员确定优先级、负责人和截止日期。
- 内容编辑查看建议和证据，提交完成说明。
- 审批人审核任务，完成、拒绝或要求继续修改。
- 所有人可查看任务历史和状态变化原因。

## 3. 任务字段

- 标题、描述、任务类型和来源 Finding。
- 目标项目、页面、问题、实体或报告。
- 原始证据快照和建议。
- 优先级及其分项。
- 负责人、协作者、截止日期。
- 验收条件和验证方式。
- 状态、完成说明、审核意见。
- 创建、更新和状态事件历史。

## 4. 状态机

```text
todo → in_progress → in_review → done
  │         │             ├→ changes_requested → in_progress
  │         └→ cancelled  └→ in_progress（要求修改）
  └→ cancelled
```

- done 只能由具有审核权限的用户从 in_review 转换。
- changes_requested 必须填写原因，可重新进入 in_progress。
- cancelled 需要原因，默认终态；恢复需 ProjectAdmin 创建显式事件。
- 非法转换返回 409，不修改任务。

## 5. 数据模型

- `optimization_tasks`：任务主体、来源、状态、优先级和版本。
- `task_evidence_links`：Finding、页面、回答、指标或报告引用。
- `task_acceptance_items`：验收条件和完成状态。
- `task_assignments`：负责人和协作者。
- `task_events`：不可变状态、字段和评论事件。
- `task_comments`、`task_attachments`：讨论和受控附件。

来源证据保存版本引用；当前页面变化不能让历史任务失去创建依据。

## 6. API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/findings/{id}/optimization-tasks` | 从 Finding 创建 |
| GET | `/api/v1/optimization-tasks` | 列表、筛选和看板 |
| GET/PATCH | `/api/v1/optimization-tasks/{id}` | 详情和字段编辑 |
| POST | `/api/v1/optimization-tasks/{id}:transition` | 条件状态转换 |
| POST | `/api/v1/optimization-tasks/{id}/comments` | 评论 |
| GET | `/api/v1/optimization-tasks/{id}/events` | 完整历史 |

PATCH 和 transition 使用版本条件，防止并发覆盖。

## 7. 实现细节

1. 从 Finding 创建时复制来源版本、证据引用、建议和默认验收模板，不复制大正文。
2. 同一 Finding 可以有多个任务，但系统提示现有开放任务，防止无意重复。
3. 优先级默认继承报告分项；人工调整保存原因。
4. 状态机由后端领域服务统一实现，前端只展示允许动作。
5. 状态转换和 Task Event 在同一数据库事务提交。
6. 任务完成不自动关闭来源 Finding；审核人可选择标记 Finding resolved，并记录关联。
7. Evidence 被删除或过期时保留摘要、哈希和不可用状态，不重新指向其他版本。
8. 通知通过 Outbox 产生，通知失败不回滚任务状态。
9. P0 附件限制类型和大小，进入私有对象存储并做恶意文件扫描。

## 8. UI

- 列表和看板支持状态、类型、负责人、优先级、截止日和来源筛选。
- 任务详情展示来源 Finding、证据、建议、验收清单和历史时间线。
- 状态按钮只显示当前合法转换，拒绝/取消需要原因 Dialog。
- Evidence Drawer 保持报告和页面的原权限校验。
- 逾期、阻塞和无负责人任务有明确提示。

## 9. 权限

- Analyst：创建、编辑普通任务、分配允许成员。
- Editor：处理分配给自己的任务并提交审核。
- Approver/ProjectAdmin：完成、拒绝和恢复取消任务。
- Viewer：只读。
- 任何人不能通过任务链接绕过原证据访问权限。

## 10. 异常与边界

- Finding 已被其他任务解决：创建时提示但允许有理由的独立任务。
- 负责人被停用：任务保留，标为需重新分配。
- 并发状态转换：只有一个成功，另一个得到最新状态和 409。
- 截止日期早于当前时间：允许但要求确认并记录。
- 证据已删除：任务仍可读，但显示证据不可用和删除原因。

## 11. 验收标准

- AC-01：用户可从任一 Finding 创建任务，自动关联问题、证据、建议、负责人、截止日和验收条件。
- AC-02：任务严格执行规定状态机，非法转换返回 409 并记录失败操作。
- AC-03：done 必须经过 in_review 和有审核权限用户确认。
- AC-04：每次状态、优先级、负责人和验收条件变化具有操作者、时间和前后值。
- AC-05：并发编辑通过乐观锁防止静默覆盖。
- AC-06：任务引用历史版本证据，来源当前数据变化不改变任务依据。
- AC-07：无权限用户不能通过任务读取受限原始回答、网页或报告。
- AC-08：完成任务不会无记录地自动修改生产内容或自动关闭 Finding。
