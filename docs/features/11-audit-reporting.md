# FEAT-11：GEO Audit 报告与导出

> 功能版本：V1.0｜产品版本：P0 V1.0｜状态：研发评审稿  
> 需求：RPT-001～RPT-004｜对齐：SPEC-01、03、10 V1.0

## 1. 功能目标

将一次审计的协议、样本、指标、技术 Finding、内容 Finding 和优化建议组织为版本化报告，使用户能从任何结论下钻到原始证据，并安全导出 PDF/CSV。

## 2. 报告结构

1. 执行摘要和限制声明。
2. 数据范围：问题、引擎、渠道、地区、语言、时间和样本。
3. 四类核心指标、有效回答率和置信区间。
4. 按主题、意图、引擎和问题的表现。
5. 竞品提及/推荐对比。
6. 技术可发现性问题。
7. 内容结构和证据问题。
8. 优先级建议。
9. 协议、版本和方法附录。

部分报告必须显著显示缺失供应商、切片和完整性，不得伪装为完整审计。

## 3. 报告版本

报告绑定 Audit、协议快照、Evaluation Run、Metric Snapshot、Crawl Run、Content Analysis Run 和模板版本。任何依赖版本变化都生成新报告版本，不覆盖已发布报告。

状态：`draft → generating → ready → published | failed | superseded`。

## 4. 问题优先级

默认优先级由以下可解释分项形成：

- 影响范围：受影响页面、问题或回答比例。
- 置信度：规则/Judge/人工确认程度。
- 业务重要性：关联问题权重和页面类型。
- 修复成本：人工估算或规则默认。
- 风险：安全、合规、品牌错误和数据完整性。

系统展示各分项和规则版本；用户可调整业务重要性与修复成本，但必须填写原因。

## 5. 数据模型

- `reports`：依赖版本、状态、模板和发布时间。
- `report_sections`：章节数据快照或查询引用。
- `report_artifacts`：PDF/CSV、哈希、大小和对象引用。
- `finding_priorities`：分项、结果、版本和人工调整。
- `report_access_events`：查看、导出和分享审计。

## 6. API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/audits/{id}/reports` | 生成指定版本报告 |
| GET | `/api/v1/reports/{id}` | 报告元数据和章节 |
| POST | `/api/v1/reports/{id}:publish` | 发布不可变版本 |
| POST | `/api/v1/reports/{id}/exports` | 异步生成 PDF/CSV |
| GET | `/api/v1/exports/{id}` | 状态和短时下载链接 |
| GET | `/api/v1/report-evidence/{type}/{id}` | 权限校验后的证据下钻 |

P0 报告默认私有，不提供匿名公开链接。

## 7. 实现细节

1. 报告生成只读取已发布或冻结的依赖版本，不读取“最新”可变数据。
2. Report Worker 生成临时工件，验证页数、哈希和关键章节后原子发布对象引用。
3. PDF 使用固定模板、嵌入字体和分页规则；CSV 防止公式注入，统一 UTF-8 BOM 策略。
4. 每张图表和 Metric Card 带 Evidence Query；下钻重新执行租户/项目权限校验。
5. 报告包含协议、渠道、模型可见性、Judge、指标、样本和限制声明。
6. Finding 优先级计算版本化，人工调整不改变原始机器分项。
7. 导出采用短时签名 URL，生成、下载和失败写审计日志。
8. 报告使用 React 静态打印模板和固定 Playwright Chromium `page.pdf()` 渲染；图表服务端输出 SVG，镜像固定字体与 Digest，不执行用户脚本或访问外部网络（ADR-004）。

## 8. UI

- 报告首页有执行摘要、质量警告和核心指标。
- 指标、问题和 Findings 可打开 Evidence Drawer。
- 支持按引擎、主题、渠道筛选，但导出需显示所选范围。
- 优先级列表展示构成、证据和“创建任务”操作。
- 导出中心显示队列、有效期、大小和失败原因。

## 9. 异常与边界

- 样本完整性不足：只允许生成部分报告，显示阻断原因。
- PDF 生成失败：报告数据保持 ready，工件任务单独重试。
- 原始证据已过保留期：显示证据不可用及删除时间，不能伪造摘要来源。
- 报告被新版本替代：旧 URL 仍按权限可读并显示 superseded。
- CSV 单元格以 `= + - @` 开头：转义以阻止公式执行。

## 10. 验收标准

- AC-01：总览包含样本范围、协议、四类指标、技术问题、内容问题和高优先级建议。
- AC-02：任一指标和结论可下钻到问题、原始回答、Judge 证据、引用或页面版本。
- AC-03：PDF/CSV 包含生成时间、范围、分子分母、口径、版本和限制声明。
- AC-04：优先级构成透明，人工调整保留前后值、操作者和原因。
- AC-05：新 Judge、指标或模板生成新报告版本，不覆盖旧报告。
- AC-06：无权限用户无法通过直接 URL、导出 ID 或签名 URL 获取报告/证据。
- AC-07：部分报告显著展示缺失数据，并且不进入正式连续趋势。
- AC-08：CSV 公式注入、PDF 脚本注入和超大导出测试通过。
