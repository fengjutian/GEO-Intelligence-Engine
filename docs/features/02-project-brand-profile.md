# FEAT-02：项目、品牌与竞品档案

> 功能版本：V1.0｜产品版本：P0 V1.0｜状态：研发评审稿  
> 需求：PRJ-001～PRJ-005｜对齐：PRD V1.0；SPEC-03 V1.0；SPEC-08 V1.0

## 1. 功能目标

建立 GEO Audit 的业务上下文，维护项目、目标品牌、产品、别名、官网、竞品、地区、语言和默认测量配置，为抓取、问题生成和 Answer Judge 提供版本化输入。

## 2. 用户故事

- 项目管理员通过向导创建项目并完成最小品牌配置。
- 分析师维护品牌别名、产品、行业、客户和应用场景。
- 用户配置竞品，并明确主品牌与竞品的产品映射。
- 项目配置修改后，历史审计仍使用启动时快照。
- 管理员可以归档项目而不删除历史数据。

## 3. 项目创建向导

步骤：基本信息 → 品牌与官网 → 产品/场景 → 竞品 → 区域语言 → 默认协议预览 → 确认。

最小必填：项目名、品牌正式名、官网、默认语言、地区和时区。官网规范化后必须是 HTTP/HTTPS 公网域名，授权状态可在创建后完成。

## 4. 数据模型

- `projects`：名称、状态、时区、默认 locale、当前配置版本。
- `brands`：规范名、描述、官方域名、状态。
- `brand_aliases`：别名、旧称、产品简称、语言、是否启用。
- `products`：名称、类别、描述、确认状态和来源。
- `brand_context_items`：行业、客户类型、技术、应用场景。
- `competitors`、`competitor_aliases`、`competitor_products`。
- `project_config_versions`：每次发布配置的不可变快照和哈希。

草稿编辑当前配置；启动审计时引用已发布快照，不直接读取可变表。

## 5. API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/api/v1/projects` | 列表与创建 |
| GET/PATCH | `/api/v1/projects/{id}` | 详情与基本配置 |
| POST | `/api/v1/projects/{id}:archive` | 归档，不物理删除 |
| POST | `/api/v1/projects/{id}/config-versions` | 发布配置快照 |
| CRUD | `/api/v1/projects/{id}/brands/...` | 品牌和别名 |
| CRUD | `/api/v1/projects/{id}/products/...` | 产品和场景 |
| CRUD | `/api/v1/projects/{id}/competitors/...` | 竞品和产品映射 |

PATCH 使用 `If-Match` 或 version 字段做乐观锁，冲突返回 409。

## 6. 实现细节

1. 品牌和别名同时保存原文与规范化值；规范化处理大小写、Unicode、常见标点和空白，不删除具有语义的字符。
2. 别名冲突检查覆盖主品牌、竞品和产品；冲突允许保存为待确认，但不能直接进入自动 Judge。
3. 官网验证通过 DNS TXT、指定文件或管理员授权状态完成。
4. 产品、行业和场景具有 `machine_suggested/human_verified/rejected` 状态。
5. 发布配置前检查未解决别名冲突、无官网、无语言/地区等阻断项。
6. 配置快照包含品牌、别名、产品、竞品、locale 和默认协议引用，写入后只读。
7. 项目归档后禁止新抓取和审计，但允许查看、导出和恢复。
8. 物理删除不属于归档流程，走独立数据删除任务和冷静期。

## 7. UI

- 项目列表：状态、品牌、最近审计、负责人和操作。
- 创建向导支持保存草稿和返回修改。
- 品牌档案使用分区表单；别名、产品和竞品使用可编辑表格。
- 冲突以 Evidence Panel 展示，并要求确认目标实体。
- 发布配置显示 Diff，说明将影响未来审计、不改变历史数据。

## 8. 权限

- ProjectAdmin：创建、编辑、发布、归档。
- Analyst：编辑品牌内容，但发布配置可由项目策略限制。
- Viewer：只读。
- 只有 Owner 可发起物理删除。

## 9. 异常与边界

- 官网重定向到其他域名：展示最终域名，要求用户确认，不自动替换。
- 品牌名与普通名词相同：必须配置上下文或域名证据。
- 主品牌被添加为竞品：阻止保存。
- 并发编辑：后提交者得到版本冲突和最新 Diff。
- 归档时存在运行任务：先阻止新任务，允许当前任务完成或由用户取消。

## 10. 验收标准

- AC-01：用户可用最小必填字段创建项目，并在完成向导后发布 V1 配置快照。
- AC-02：品牌正式名、别名和旧称支持逐项启停，Judge 只读取已发布且启用的值。
- AC-03：产品、行业、客户和场景都具有唯一 ID、来源、确认状态和更新时间。
- AC-04：主品牌与竞品名称冲突时系统要求消歧，不能静默归类。
- AC-05：修改当前品牌档案后，已完成和运行中的审计快照内容不变化。
- AC-06：项目归档后无法启动抓取和审计，历史报告仍可读取。
- AC-07：项目语言、地区和时区在所有后续审计页面和导出中正确显示。
- AC-08：无权限用户不能编辑、发布或归档项目。
