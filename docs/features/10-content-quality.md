# FEAT-10：内容结构与证据质量

> 功能版本：V1.0｜产品版本：P0 V1.0｜状态：已批准  
> 层级：P0-S｜判定与排期见 [功能优先级规划](../FEATURE-PLAN.md)  
> 需求：CON-001～CON-002｜对齐：SPEC-03、04、08 V1.0

## 1. 功能目标

分析页面是否具备清晰、可提取、可验证的答案结构，并识别标题、摘要答案、FAQ、术语解释、事实/观点边界和证据质量问题，为 GEO Audit 报告提供带页面证据的内容 Finding。

## 2. 分析范围

### 2.1 内容结构

- 页面主题和主标题是否明确。
- H1-H6 层级是否合理。
- 首屏/主题段是否存在直接答案。
- 长内容是否按语义标题和段落分块。
- FAQ 是否包含真实问题和独立答案。
- 术语是否在首次出现附近解释。
- 列表、表格和步骤是否语义完整。
- 事实陈述和主观观点是否可以区分。

### 2.2 证据质量

- 作者、机构、发布日期和更新时间。
- 数据、统计、研究、案例和引用来源。
- 外部链接是否可访问、是否支持邻近主张。
- 数值是否具有单位、时间范围和数据来源。
- 内容是否存在明显过期标志。

P0 只判断证据是否存在、结构是否清晰和来源是否可追踪，不宣称自动验证全部事实真伪。

## 3. 输入与输出

输入为固定 `page_content_id`、DOM 块、正文、链接、Schema、页面语言和解析器版本。输出为分析运行、页面评分分项、Finding、证据 locator 和分析器版本。

系统可以展示分项信号，但 P0 不输出无法解释的单一“内容质量总分”。

## 4. 规则体系

| 类别 | 示例规则 |
|---|---|
| 结构 | 缺 H1、多 H1、标题跳级、超长无标题段落 |
| Answer First | 标题后的前 N 个正文块无直接定义/回答 |
| FAQ | 问题无答案、答案依赖隐藏交互、重复 FAQ |
| 术语 | 高频专业缩写无解释 |
| 事实边界 | 大量绝对化结论无来源或限定条件 |
| 新鲜度 | 无日期、明显过期年份、版本信息冲突 |
| 证据 | 数值无来源、引用失效、来源与主张距离过远 |

每条规则包括 code、版本、适用语言/页面类型、严重度默认值、检测逻辑和证据要求。

## 5. 数据模型

- `content_analysis_runs`：crawl、analyzer_version、状态和配置。
- `content_blocks`：语义块、类型、文本哈希和 DOM locator。
- `content_signals`：规则原始信号和值。
- `findings`：问题、严重度、置信度、建议和证据。
- `evidence_references`：页面块、链接或结构化数据引用。

同一页面内容哈希和分析器版本可复用结果。

## 6. API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/crawl-runs/{id}/content-analysis-runs` | 发起分析 |
| GET | `/api/v1/content-analysis-runs/{id}` | 状态和汇总 |
| GET | `/api/v1/page-contents/{id}/content-signals` | 页面信号 |
| GET | `/api/v1/content-findings` | 按规则、严重度和页面筛选 |
| PATCH | `/api/v1/findings/{id}` | 人工确认、忽略或调整业务重要性 |

## 7. 实现细节

1. 先用确定性 DOM/文本规则检测结构，再用模型处理语义判断；模型调用统一经过 Gateway。
2. Answer First 按页面类型使用不同模板，不能把首页、产品页和文档页用同一阈值判定。
3. 事实/观点分析输出候选和证据，不把模型推断包装为事实核验结论。
4. 引用可访问性通过受控 Crawler 检查，不由 Judge/LLM 任意请求 URL。
5. 每条 Finding 包含影响说明、置信度、页面版本、证据片段和建议，而非只有规则代码。
6. 严重度由技术默认值、影响范围、置信度、修复成本和业务重要性组成；人工调整保留原因。
7. 分析器升级产生新 Run，不覆盖旧 Finding；报告绑定指定版本。
8. 多语言规则按 locale 启用，未知语言只运行语言无关规则并提示覆盖不足。

## 8. UI

- 内容概览按规则类别、页面类型和严重度展示。
- 页面详情高亮标题、答案块、事实候选和引用。
- Finding Drawer 展示规则说明、证据、建议、置信度和版本。
- 支持确认、误报、接受风险和转优化任务。
- 评分不得只用颜色，必须显示分项和具体问题。

## 9. 异常与边界

- 页面正文提取失败：不运行语义规则，生成解析质量 Finding。
- 引用目标不可访问：标记无法验证，不直接判为虚假。
- 页面无发布日期但内容并不时效敏感：降低严重度，由页面类型规则决定。
- FAQ 由客户端渲染：使用渲染 DOM 判断，并保留静态差异。
- 模型分析失败：确定性规则结果仍可发布，语义部分标记缺失。

## 10. 验收标准

- AC-01：能够检测标题层级、直接答案、语义分块、FAQ、术语和事实/观点边界，并关联页面证据。
- AC-02：能够识别作者、日期、统计、研究、案例和引用来源的存在与结构。
- AC-03：无法验证事实或引用时显示 unknown/待复核，不自动判定为真实或虚假。
- AC-04：同一页面内容和分析器版本重复运行得到相同确定性规则结果。
- AC-05：每条 Finding 可回到页面版本、DOM/文本位置和规则版本。
- AC-06：内容分析失败不影响已保存抓取结果，支持独立重跑。
- AC-07：用户可把 Finding 标为确认、误报或接受风险，机器结果和人工结论并存。
- AC-08：分析器在 [内容质量黄金测试集](../../tests/golden/content-quality/README.md) 达到各项分层门槛；未达标语义规则只能标记实验性并进入人工复核。
