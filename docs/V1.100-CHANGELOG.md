## CMS 连接器：静态站点内容目录

发布目标不再只有 webhook，新增 `kind` 区分连接器：

| kind | 行为 |
|---|---|
| `webhook` | 签名 POST 到公开端点（原有能力） |
| `filesystem` | 把草稿渲染成文件写入静态站点内容目录 |

- 迁移 `000035_publish_connector_kind`：`publish_targets` 增加 `kind` 与 `config_json`。
- 写入路径：`$GEO_PUBLISH_ROOT/<projectId>/<kind>.<ext>`（默认 `.run/publish-out`），扩展名 `jsonld→json`、`llms_txt→txt`、其他 `md`。
- `llms_txt` 渲染为**纯文本**（优先取 `content`，兼容 `text`），其余草稿输出缩进 JSON。
- 回滚对文件系统连接器是**删除该文件**，站点生成器自然不再收录。
- 未知 kind 返回 422 `PUBLISH_TARGET_INVALID`。

## 实测

| 场景 | 结果 |
|---|---|
| 设置 `kind=filesystem` | 200 |
| `kind=carrier_pigeon` | 422 |
| 发布已审批的 `llms_txt` 草稿 | delivered，写出 `llms_txt.txt` |
| 文件内容 | `# 飞书 …` 纯文本（非 JSON 包装） |
| 回滚 | delivered，文件已删除 |
| 恢复 webhook 目标 | 200 |
| 证据 | `.run/geo-cms-connector-verification.json` |

## 已知边界

- 只有两种连接器；Git PR / WordPress / Contentful 未实现（接口已按 kind 扩展，加一种只需实现 deliver 分支）。
- 文件系统写入本机目录，部署链路由站点自身的构建流程负责，平台不触发部署。
- `config_json` 已入库但暂未使用（预留给 Git 连接器的仓库/分支/路径）。
- 回滚只删除文件，不恢复上一版本内容（多版本历史未保留）。
