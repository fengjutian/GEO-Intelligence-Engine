## 从已发布版本克隆草稿

新增：

```text
POST /question-sets/{id}/versions/{versionId}/clone
```

- 源版本必须是 published；
- 只允许克隆到空白的当前 draft；
- draft 已有问题返回 409；
- 复制问题文本、hash、类型、权重、状态与属性；
- 返回 draft version 与复制条数。

### 实测

- v2 已发布 30 条；
- 自动生成空 draft v3；
- 克隆 v2 → v3：30 条；
- v2→v3 Diff：0 added / 0 removed / 0 changed。

UI 在“版本 Diff”面板新增“克隆到草稿”。

## 竞品联动别名匹配

- `competitive-insights` 读取启用中的竞品别名；
- 每个竞品按 canonical name + alias 顺序匹配 share 实体；
- 未命中返回 0 份额。

### 说明

Share API 输出的实体名本身来自竞品 canonical name，因此当前数据下 exact match 总会先命中，别名 fallback 没有可复现的真实差异样本。别名匹配逻辑已接入，但未用“share 实体名=别名”的 fixture 验证。

## 报告默认模板精简

- `CreateReport` 默认模板改为 `report-v2`；
- `report-v2` 只包含四段：
  1. `geo_summary`
  2. `competitive_landscape`
  3. `content_trust`
  4. `metrics`
- `report-v1` 保留 11 段完整模板，兼容历史。
- Web 生成报告默认请求 `report-v2`。

| report-v1 | 11 |

## 边界

- 克隆只复制到空白 draft，不自动创建新版本；
- 克隆后仍受草稿版本编辑/发布约束；
- 别名匹配未做别名命中 fixture；
- report-v2 不含 findings/priorities/limitations；这些只在 report-v1 中保留；
- PDF 头部仍复用 summary 字段，report-v2 下部分头部统计显示 “—”。
