## 执行失败告警演练

尝试取消刚创建的审计，但审计已快速完成，取消返回 409。

为验证告警链路，采用受控故障注入：

- 将 `01a1de62…` 的 status 直接改为 `failed`；
- 等待 Runner 下一轮检查；
- 生成告警 `audit_execution_failed`；
- 告警状态 open → resolved。

结果：

| 项 | 结果 |
|---|---|
| 告警 ID | `cdb75859…` |
| 类型 | `audit_execution_failed` |
| 消息 | scheduled audit finished with status failed |
| 解决后状态 | resolved |
| 证据 | `.run/monitoring-drill-verification.json` |

## 结论

- 双实例不会重复创建 monitor 审计；
- 执行失败告警链路可用；
- 取消演练失败是因为审计完成过快，不是告警缺陷；
- 真实“运行中取消”仍需一个长耗时审计或延迟 Worker。
