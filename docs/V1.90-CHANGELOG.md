# GEO Intelligence P0 V1.90 增量记录

> 状态：已记录｜日期：2026-11-15｜前置基线：V1.89，待项目负责人确认

## 采集协议加固

### 1. 编码防呆

- 新增校验 `ANSWER_ENCODING_SUSPECT`：连续 3 个以上 `?`，或长度 ≥12 且 `?` 占比 ≥1/3 时拒绝。
- 背景：实测中用非 UTF-8 客户端提交时，中文被替换成 `?` 仍能入库并通过判定，产生"看似合法"的错误数据。

### 2. 渠道白名单登记表

- 新增 `capture_surfaces`（provider + product 唯一），迁移预置 openai/chatgpt、perplexity/perplexity、google/ai-overview、microsoft/copilot、bytedance/doubao。
- 提交时校验 `surface.provider/product` 必须已登记且启用，否则 `SURFACE_UNSUPPORTED`。
- 新增 `GET /api/v1/capture-surfaces` 与 `POST /api/v1/capture-surfaces`（Owner，`manage_keys`）。

### 3. 采集后自动重算指标

- 一批采集全部处理完后，对本次有 `accepted` 的审计自动调用 `RecomputeMetrics`。
- 采集答案因此进入 `metrics-v1h` 快照，无需再手工触发重算。
- 重算失败不影响采集入库（错误被忽略，指标保留上次快照）。

## 测试

- `looksMojibake`：连续问号、问号占比；正常中文与英文单问号不误判；
- `ValidateCapture` 拒绝乱码答案；
- 既有采集校验/验签/幂等用例保持通过。

## 已知边界

- 编码校验是启发式，正常文本里出现 "???" 的极端情况会被误拒（可降级为警告，待产品确认）。
- 白名单为全局表，暂不支持按租户隔离或只读导入。
- 自动重算只重建 `metrics-v1h`，不刷新已发布的报告（报告仍冻结生成时的快照）。
- 同一次采集若跨多个审计，会逐个审计重算，批量很大时注意耗时。
