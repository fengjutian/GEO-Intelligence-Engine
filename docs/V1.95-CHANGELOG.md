# GEO Intelligence P0 V1.95 增量记录

> 状态：已记录｜日期：2026-11-15｜前置基线：V1.94，待项目负责人确认

## Model Worker 并发

- `cmd/model-worker` 从"单循环串行领取"改为 N 个 goroutine 并行领取，N 由 `GEO_MODEL_WORKER_CONCURRENCY` 控制（默认 4，上限 16）。
- 每个槽位使用独立 worker id（`<base>-00` …），便于从 `lease_owner` 区分。
- 领取仍依赖 `FOR UPDATE SKIP LOCKED`，多 goroutine 不会抢到同一样本。
- 网关侧 `GEO_MODEL_MAX_CONCURRENCY`（默认 4）继续约束单供应商并发，两者需匹配。

## 实测

| 场景 | 吞吐 |
|---|---|
| 并发 1（原） | 约 2 样本/分钟 |
| 并发 4（现） | 约 20 样本/分钟 |

120 样本审计的预计耗时从约 57 分钟降到约 6 分钟。

## 已知边界

- 并发提升会同步抬高供应商侧的瞬时请求量，需与 RPM/配额匹配；
- 单 worker 进程内的并发，不支持跨进程协调（多副本仍靠 SKIP LOCKED）；
- 未做自适应并发（按 429 自动降速）。
