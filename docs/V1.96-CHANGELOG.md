# GEO Intelligence P0 V1.96 增量记录

> 状态：已记录｜日期：2026-11-15｜前置基线：V1.95，待项目负责人确认

## 测量口径修复：移除品牌 priming

**发现**：`cmd/model-worker` 在每次调用都把品牌名写进 system prompt（"The brand is 飞书 (feishu.cn)"）。这让模型被提示后自然提及品牌，指标实际测的是"模型有没有复述我们告诉它的名字"，而不是"模型是否知道并推荐这个品牌"。

**证据（同一批 40 个问题、同一模型）**：

| 品牌 | priming | 中性提示 |
|---|---|---|
| 飞书（真实） | 97.5%（117/120） | **76.5%（91/119，CI 68.1–83.2）** |
| 极光协作（虚构） | **74.8%（92/123）** | **0%（0/41）** |

虚构品牌在 priming 下能拿到 74.8% 的提及率，去掉后归零——说明该指标此前被系统性高估。

**修复**：system prompt 只保留"回答买家问题 / 语言 / 市场 / 具体且不编造引用"，不再注入品牌名与域名。品牌识别仍由 Judge 负责。

**影响**：

- 此前所有审计（`audit-prompt-v1`）的提及率、推荐率、份额均偏高，约 +21 个百分点；
- 与修复后的审计**不可直接比较**，实验基线需要重建；
- 新增 `promptTemplateVersion` 取值 `audit-prompt-v2-neutral` 标识新口径。

## 新的可信基线（飞书，40 题 × 3 样本 = 120）

| 指标 | 结果 | 95% CI |

## 测试

- 新增 `TestBuildMessagesDoesNotPrimeTheBrand`：system prompt 不得包含品牌名或域名，且保留语言/市场上下文。

## 已知边界

- 历史审计数据未回填，报告里的旧数字需标注口径版本；
- 中性提示下模型仍可能因问题文本本身含品牌名而提及（如"飞书适合多少人"），这属于合理提及；
- 实验的 baseline/treatment 必须同口径，跨口径比较无效。
