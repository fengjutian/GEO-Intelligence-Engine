# GEO 论文分析与项目借鉴建议

> 论文：Pranjal Aggarwal 等，*GEO: Generative Engine Optimization*，KDD 2024  
> 本地原文：[GEO-Generative-Engine-Optimization-KDD-2024.pdf](./GEO-Generative-Engine-Optimization-KDD-2024.pdf)  
> 在线原文：[arXiv:2311.09735](https://arxiv.org/pdf/2311.09735)

## 核心判断

这篇论文最重要的贡献，不是证明“加统计数字就能让 ChatGPT 推荐品牌”，而是首次把 GEO 形式化为一个可实验的问题：

```text
内容干预
→ 生成式搜索回答变化
→ 来源可见度变化
→ 比较不同干预的效果
```

它为 GEO 提供了三个基础部件：

1. 一套生成式搜索的抽象模型；
2. 一组来源可见度指标；
3. 一套内容干预实验方法。

但论文研究的主要是：**当来源已经进入候选集合后，修改来源内容会不会让它在最终答案中占据更多篇幅和更好位置。**

它没有充分研究更关键的前半程：

```text
网页发布
→ 搜索引擎收录
→ 查询改写
→ 候选召回
→ 来源排序
→ 进入模型上下文
```

所以，这是一篇很好的“答案合成阶段优化”论文，却不是完整的 GEO 工程答案。

## 一 论文解决了什么问题

论文将 Generative Engine 抽象为：

```text
用户问题
→ 查询改写
→ 搜索引擎召回来源
→ 来源摘要
→ LLM 综合回答
→ 行内引用
```

传统 SEO 通常用排名衡量可见度，但生成式答案不是链接列表。来源可能：

- 出现在开头或结尾；
- 支撑一句或多句内容；
- 与其他来源共同支撑一句话；
- 被引用但对回答贡献很小；
- 对答案产生重要影响，却不一定处于“第一名”。

因此，论文把 GEO 的目标定义为：

> 在不知道生成引擎内部算法的情况下，通过修改网站内容，提高该来源在生成答案中的可见度。

这是一个黑盒优化问题。

## 二 论文提出的可见度指标

### 1. Word Count

计算一个来源所支撑句子的字数占整个回答字数的比例。

如果一句话同时引用多个来源，则将这句话的字数平均分配给这些来源：

```text
Citation Word Share
= 来源所支持的回答字数
  / 回答总字数
```

这个指标比简单的“是否引用”更有信息量。

例如：

```text
回答 A：品牌官网仅出现在最后一句引用中
回答 B：三段核心结论都引用品牌官网
```

两者的官网引用率都是 100%，但来源影响力显然不同。

### 2. Position Adjusted Word Count

论文进一步对引用位置加权。越靠前的句子权重越高，位置权重按指数衰减。

可以简化理解为：

```text
来源可见度
= Σ 引用句字数 × 位置权重
  / 回答总字数
```

这是本文最值得本项目直接借鉴的确定性指标。

它的优点是：

- 不依赖 LLM Judge；
- 可以从答案和引用位置直接复算；
- 同时体现引用篇幅和出现位置；
- 很适合进入不可变指标快照。

### 3. Subjective Impression

论文还定义了七个主观维度：

- 引用内容与问题的相关性；
- 来源对答案的影响力；
- 引用材料的独特性；
- 主观位置显著度；
- 主观内容占比；
- 用户点击引用的可能性；
- 来源材料的多样性。

这些指标由 GPT-3.5 按类似 G-Eval 的方法打分。论文同时承认 G-Eval 分数校准不佳，因此将其均值和方差归一化到 Position-Adjusted Word Count 的分布。

这部分有启发性，但可信度明显弱于确定性指标。对本项目而言，适合保留分项评分和理由，不适合把一个 LLM 总分当成核心 KPI。

## 三 九种内容干预方法

论文测试了九种 GEO 方法：

| 方法 | 干预内容 |
|---|---|
| Authoritative | 改成更权威、更有说服力的语气 |
| Statistics Addition | 增加量化统计数据 |
| Keyword Stuffing | 增加查询相关关键词 |
| Cite Sources | 增加可信来源 |
| Quotation Addition | 增加权威引语 |
| Easy to Understand | 简化语言 |
| Fluency Optimization | 改善流畅性 |
| Unique Words | 增加少见词汇 |
| Technical Terms | 增加技术术语 |

这些方法本质上分为三类：

### 表达优化

- 简化语言；
- 改善流畅性；
- 调整权威语气；
- 增加技术术语。

### 证据增强

- 增加统计数据；
- 增加来源；
- 增加引语。

### 传统 SEO 式处理

- 关键词堆砌；
- 增加少见词汇。

论文发现证据增强整体最有效，流畅性也有积极效果；关键词堆砌基本没有带来可见度改善。

## 四 实验是怎么做的

### 数据集

GEO-Bench 包含约 10,000 个问题，来自九类数据源：

- MS MARCO；
- ORCAS；
- Natural Questions；
- AllSouls；
- LIMA；
- Davinci Debate；
- Perplexity Discover；
- ELI5；
- GPT-4 生成问题。

划分为：

```text
训练集 8,000
验证集 1,000
测试集 1,000
```

问题分布约为：

```text
信息型 80%
交易型 10%
导航型 10%
```

每个问题绑定 Google 搜索前五个结果的清洗正文，并标注领域、难度、意图、问题性质、敏感性和答案类型。

这意味着它适合研究通用信息型问答，但与企业采购、品牌比较、供应商选择等商业 GEO 问题仍有较大分布差异。

### 生成引擎

实验引擎的结构是：

1. 使用 Google 搜索结果；
2. 固定取前五个来源；
3. 把五个来源全文交给 GPT-3.5 Turbo；
4. 要求每句话附带引用；
5. 温度设为 0.7；
6. 每个实验生成五次回答。

每个问题随机选择一个来源进行优化，同一问题下的不同 GEO 方法都修改同一个来源，以便横向比较。

## 五 主要实验结果应该怎样理解

### 1. 整体结果

论文报告：

- 最优方法在 Position-Adjusted Word Count 上提高约 41%；
- 在 Subjective Impression 上提高约 28%；
- 引用、引语和统计增强通常表现最好；
- 流畅性和易读性也能产生改善；
- 关键词堆砌效果很弱。

这里的“40%”是特定实验指标上的相对提升，不是：

- 品牌提及率提升 40%；
- 网站流量提升 40%；
- 搜索召回概率提升 40%；
- 在所有平台都提升 40%。

### 2. 低排名来源获益更明显

论文按原始搜索位置分析后发现，第五名来源使用 Cite Sources、Quotation Addition、Statistics Addition 时，相对提升接近或超过 100%；但这些方法对第一名来源有时反而产生负面效果。

例如 Cite Sources 的相对变化为：

| 原始排名 | 可见度变化 |
|---:|---:|
| 第 1 名 | -30.3% |
| 第 2 名 | +2.5% |
| 第 3 名 | +20.4% |
| 第 4 名 | +15.5% |
| 第 5 名 | +115.1% |

这个结果不能简单解释为“越低排名，增加引用越有效”。

还存在数学原因：第五名来源的基线可见度本来可能很低。相对增长公式的分母很小时，少量绝对改善就会产生非常大的百分比。

因此，本项目同时需要记录：

```text
绝对提升 = Treatment Rate - Baseline Rate
相对提升 = 绝对提升 / Baseline Rate
```

不能只展示相对提升。

### 3. 方法存在领域差异

论文发现：

- Cite Sources 更适合事实型问题；
- Statistics Addition 对法律、政府、辩论和意见类问题较有效；
- Quotation Addition 对人物、社会、历史和解释型问题较有效；
- Authoritative 对辩论类问题更有帮助；
- Fluency Optimization 与其他策略组合时表现较稳定。

这支持“按问题类型推荐干预”，反对所有页面套用同一个 GEO 模板。

### 4. 组合策略可能优于单项策略

论文对四种较优方法进行了两两组合测试：

- 流畅性；
- 统计数据；
- 引用来源；
- 引语。

流畅性与统计数据的组合最好，比最佳单一策略再高约 5.5%。但组合实验只使用了约 200 个样本，证据强度弱于完整测试集。

### 5. Perplexity 实验

论文还在真实 Perplexity 上进行了验证：

- Quotation Addition 的 Position-Adjusted Word Count 提升约 22%；
- Statistics Addition 的 Subjective Impression 提升最高约 37%；
- 关键词堆砌在客观可见度上下降。

这证明结果并非只存在于自建 GPT-3.5 引擎中，但仍然只验证了一个真实平台，而且平台状态属于 2023—2024 年时期。

## 六 这篇论文最重要的局限

### 1. 它没有测量内容修改是否提高了召回概率

实验先固定 Google 搜索前五个结果，再修改其中一个来源，然后让模型生成答案。

也就是说：

```text
论文实际测量：
已经进入上下文的来源
→ 修改内容
→ 在答案中占据更多位置

论文没有测量：
修改网页
→ 被搜索引擎重新收录
→ 进入前五个结果
→ 被生成引擎召回
```

这是全文最关键的边界。

论文自己也承认没有评估 GEO 修改对搜索排名的影响。

因此，真正的 GEO 至少要分成两个漏斗：

```text
Retrieval Visibility
页面是否被收录和召回

Answer Visibility
召回后是否被引用以及占据多少答案内容
```

### 2. 指标是零和归一化的

论文把一次回答中所有来源的 Impression 归一化为总和等于 1。

这会导致：

- 一个来源上升，其他来源必然相对下降；
- 回答长度变化可能被归一化掩盖；
- 很难区分“目标来源真的增加”还是“其他来源减少”；
- 不同回答之间的绝对引用量不完全可比。

项目实现时应同时保存：

- 原始引用字数；
- 原始回答字数；
- 归一化份额；
- 来源数量；
- 首次引用位置；
- 每个来源支持的 Claim 数量。

### 3. 优化器、回答模型和主观评审高度相关

论文主要使用 GPT-3.5：

- 生成优化内容；
- 生成最终答案；
- 评价 Subjective Impression。

这可能产生模型自偏好：一个模型生成的表达方式，可能更容易被同系列模型在回答和评价阶段偏爱。

更严格的实验应使用：

```text
优化模型 A
回答模型 B C D
Judge 模型 E
人工抽样复核
```

或者至少跨多个模型验证同一干预。

### 4. Subjective Impression 存在校准问题

论文明确表示 G-Eval 分数校准较差，所以将其均值和方差调整到客观指标附近。

这种归一化有利于表格比较，但不能让主观评分自动成为可靠的绝对测量。

本项目应：

- 保存每一个子指标；
- 保存评分理由；
- 冻结 Judge Prompt 和模型版本；
- 进行人工一致性验证；
- 不把归一化后的综合分作为唯一实验主指标。

### 5. 商业问题代表性不足

GEO-Bench 中约 80% 是信息型问题，交易型和导航型各只有约 10%。

但企业 GEO 往往最重视：

- 哪个品牌更好；
- 哪个产品适合某种应用；
- 供应商比较；
- 价格与采购；
- 推荐名单；
- 技术规格与认证。

所以 GEO-Bench 适合做通用算法回归，不应替代项目自己的买家问题库。

### 6. 只研究单轮回答

论文主体实验是单轮问答。真实用户可能通过追问逐渐缩小决策范围：

```text
有哪些品牌
→ 哪个适合制造业
→ 比较 A 和 B
→ 哪个在中国有服务网络
→ 最终推荐哪个
```

品牌可能在第一轮没有出现，却在第三轮被推荐。当前项目后续应该增加会话级指标，而不只是单轮问题指标。

### 7. 内容真实性缺少强约束

论文把增加统计、引用和引语作为干预手段，但没有建立充分的 Claim—证据核验机制。

生产系统不能让 LLM 自行补造：

- 百分比；
- 调研机构；
- 专家引语；
- 认证；
- 客户案例。

所有增强内容都应变成：

```text
verified_statistic_addition
verified_citation_addition
verified_quote_addition
```

并要求绑定真实证据快照。

## 七 对当前项目的直接借鉴

### 第一优先级 增加客观来源可见度指标

建议在现有 Judge 中加入：

```text
citation_word_count
citation_word_share
first_citation_sentence_index
position_adjusted_word_share
supported_claim_count
exclusive_supported_claim_count
```

其中 `position_adjusted_word_share` 可以直接借鉴论文公式，并作为确定性指标进入指标快照。

### 第二优先级 建立干预类型注册表

```text
Intervention
- type
- version
- target_page_version
- baseline_content_hash
- treatment_content_hash
- evidence_snapshot_id
- generator_model
- prompt_version
- validator_version
- applied_at
```

初始支持：

- `verified_citation_addition`
- `verified_statistic_addition`
- `verified_quote_addition`
- `fluency_improvement`
- `easy_to_understand`
- `answer_first`
- `faq_structure`
- `schema_markup`

关键词堆砌可以保留为负向对照，但不应作为优化建议。

### 第三优先级 分离两个实验阶段

#### 召回实验

回答：

- 页面有没有被收录？
- 是否进入生成引擎候选来源？
- 查询改写后是否还能被召回？
- 不同平台和地区是否一致？

#### 答案实验

回答：

- 进入上下文后是否被引用？
- 引用了多少内容？
- 出现在什么位置？
- 支持了哪些 Claim？
- 是否促进品牌推荐？

这能补上论文最大的缺口。

### 第四优先级 将论文结论变成先验而不是规则

系统可以初始化这样的先验：

```text
事实型问题
→ 优先测试可信引用

比较和决策问题
→ 优先测试结构化参数与第三方证据

观点和行业趋势问题
→ 优先测试已验证统计数据

历史和人物问题
→ 优先测试真实引语

解释型问题
→ 优先测试易读性与流畅性
```

但最终建议必须被本项目自己的实验数据更新，不能把论文结果固化成永久规则。

## 八 总体评价

| 维度 | 评价 |
|---|---|
| 概念创新 | 很强，首次系统形式化 GEO |
| 实验结构 | 较强，具有统一基准和对照 |
| 指标设计 | 客观指标很有价值，主观指标需谨慎 |
| 真实平台验证 | 有价值，但覆盖面有限 |
| 对当前平台的时效性 | 有限，依赖 2023—2024 年模型和平台 |
| 商业 GEO 代表性 | 中等偏弱，信息型问题占比过高 |
| 因果归因能力 | 中等，控制了答案生成阶段，但没有覆盖召回阶段 |
| 生产可用性 | 研究原型，不应直接产品化 |

最终可以把论文的价值概括为：

> 它证明了“来源已经被召回之后，内容的证据密度、表达方式和结构会影响该来源在生成答案中的可见度”；但它没有证明“修改内容就一定会让真实 AI 平台发现、召回、引用并推荐该品牌”。

对于 GEO Intelligence Engine，最正确的用法是：**吸收它的干预分类、来源可见度公式和领域实验思想，再用现有的协议冻结、真实多模型采样、证据链、人工复核和复测统计，补全它没有解决的收录、召回、真实性与因果归因问题。**
