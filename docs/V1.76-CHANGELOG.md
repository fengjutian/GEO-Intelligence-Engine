# GEO Intelligence P0 V1.76 增量记录

> 状态：已记录｜日期：2026-11-15｜前置基线：V1.75，待项目负责人确认

## 持续监测

### 数据与 API

- 迁移 `000023_monitoring`：
  - `monitoring_schedules`；
  - `monitoring_alerts`。
- API：
  - `GET/POST /projects/{id}/monitoring-schedules`；
  - `PATCH/DELETE /monitoring-schedules/{id}`；
  - `POST /monitoring-schedules/{id}/run`；
  - `GET /projects/{id}/monitoring-alerts`；
  - `PATCH /monitoring-alerts/{id}/resolve`。
- 最小间隔 60 分钟；协议必须 published。

### 执行器

- API 进程内 30 秒轮询；
- 到期 schedule 自动调用 `CreateAudit`；
- 成功更新 `last_audit_id`、重置失败次数、安排下次；
- 失败写入 `audit_create_failed` 告警，指数退避（5 分钟 × 失败次数，封顶 interval）。

### 实测

| 项 | 结果 |
|---|---|
| 创建 schedule | 成功 |
| 手动触发 | 创建新审计 |
| audit ID | `01a1de58…` |
| last_audit_id 回写 | 成功 |
| 失败次数 | 0 |
| 证据 | `.run/monitoring-verification.json` |

## 语义事实核验

### 数据与 API

- 迁移 `000024_fact_checks`：
  - `fact_check_runs`；
  - `fact_checks`。
- `POST /content-analysis-runs/{id}/fact-checks`：
  - 读取页面正文；
  - 调用 DeepSeek，只允许基于页面文本判断；
  - 提取 claim，输出 supported / unsupported / unknown + confidence + evidence；
  - 写入 pending 状态。
- `GET /projects/{id}/fact-checks?status=`；
- `PATCH /fact-checks/{id}` 确认/忽略。

### 实测

| 项 | 结果 |
|---|---|
| 模型 | deepseek-flash |
| claim 数 | 1 |
| verdict | supported |
| confidence | 0.9 |
| 人工状态 | pending → confirmed |
| 证据 | `.run/v176-verification.json` |

## 边界

- 调度器运行在单个 API 进程内；多副本会重复执行，尚无分布式锁；
- 告警只覆盖审计创建失败，不覆盖审计执行失败；
- 没有 monitoring UI；
- 事实核验为同步调用，单次最多 3 页×5 claim；
- verdict 是模型判断，不等于真实世界事实；
- 事实核验无页面 DOM locator，仅有 evidence 文本；
- 两项功能均未进报告模板/告警通知渠道。
