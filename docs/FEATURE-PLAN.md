# GEO Intelligence 功能优先级规划

> 规划版本：V1.0｜日期：2026-11-14｜状态：生效  
> 对齐：[PRD V1.0](./product-requirements.md)、[功能规格集 V1.0](./features/README.md)、[V1.0 基线](./V1.0-BASELINE.md)

## 1. 结论先行

1. **产品已经具备核心测量闭环**：项目/品牌 → 抓取 → 问题 → 协议/审计 → 模型调用 → Judge → 指标 → 报告/导出，可用真实审计数据跑通。
2. **核心功能仍未生产就绪**：真实供应商密钥、Keycloak 登录态、核心回归套件三项未完成，不能对外承诺 SLA。
3. **P0 仍有两个 Must 缺口**：FEAT-04 实体知识与 Schema、FEAT-08 人工复核队列；它们属于“支撑核心”，必须在 P0 发布前完成，但不阻塞核心闭环演示。
4. **非核心功能冻结**：持续监测、优化 Agent、实验、服务账号、附件/通知等 P1/P2/P3 能力，在核心与支撑功能通过发布门禁前不排期。

## 2. 分类规则

### 2.1 判定问题

一个功能满足以下任一条件即为**核心**：

- 阻断“第一次 GEO Audit”从创建项目到导出报告的完整链路；
- 阻断收入（客户无法完成付费交付）；
- 阻断安全/合规底线（租户隔离、权限、审计、密钥保护）；
- 缺失会导致指标不可解释或不可复算。

只满足“提升解释力/效率/自动化程度”，但不影响首次交付的，归为**支撑**或**非核心**。

### 2.2 三个层级

| 层级 | 代号 | 定义 | 排期规则 |
|---|---|---|---|
| 核心 | P0-C | 首次可用产品必须闭环的能力 | 最高优先级；未过核心门禁不开发其他层级 |
| 支撑 | P0-S | P0 发布前必须补齐，但不阻塞核心演示 | 核心门禁通过后立即排期；仍是 P0 发布阻塞项 |
| 非核心 | N1+ | P1/P2/P3 能力，提升解释、协作或自动化 | 冻结；需产品负责人书面批准才能插入 |

> 说明：分类只决定**交付顺序**，不改变 PRD 中 P0 Must 的承诺。P0-S 仍是 P0 发布门槛。

### 2.3 硬规则

1. 非核心需求不得插入当前迭代；如需插入，必须先调整发布范围并记录决策。
2. 核心门禁未通过前，不启动 P0-S；P0-S 未完成前，不启动 N1+。
3. 每个功能只允许一个“进行中”状态，避免核心链路被并行支线稀释。
4. 新增需求先回答：属于哪一层？不做会阻断什么？答案不成立则进入非核心池。

## 4. 核心功能范围（P0-C）

### 4.1 核心闭环

```text
项目/品牌 → 抓取与技术审计 → 买家问题 → 测量协议/审计
        → Model Gateway（预算/重试） → 自动 Judge
        → 指标/证据 → 报告/CSV/PDF
```

最小身份与租户隔离（FEAT-01）横切上述链路。

### 4.2 核心验收门禁

| 门禁 | 通过标准 | 当前证据 |
|---|---|---|
| 端到端成功率 | ≥ 95%（排除已确认供应商故障） | DeepSeek 真实审计 2/2 成功；MiniMax 被 429/2056 配额阻断 |
| 指标可复算 | 由原始回答 + 评估结果重算一致 | `metrics-v1` 已实现；回归脚本独立复算 16/16 通过 |
| 预算与重试 | 预算熔断、超限 422、重试分类正确 | 已验证 fake provider 场景 |
| 租户隔离 | 跨租户/非成员访问 100% 拒绝 | OIDC + membership + 项目列表过滤已验证 |
| 报告交付 | 报告含指标/发现/优先级/限制，CSV/PDF 可下载 | 已验证 |
| 身份 | 真实 OIDC 登录、Token 刷新、登出 | 后端 + Web PKCE 就绪；真实 Realm 未验收 |

### 4.3 核心开发顺序

1. **P0C-01 Web 登录态**：Keycloak 授权码 + PKCE、回调、Token 刷新、401 自动登出、开发模式兼容。
2. **P0C-02 真实供应商验收**：🟡 DeepSeek 真实审计已通过（2/2、16 指标复算、CSV 3178 字节）；MiniMax 密钥有效但 Token Plan 配额耗尽（429/2056），需充值/升级或更换密钥后补跑。
3. **P0C-03 核心回归套件**：✅ 已实现 [regression.py](../scripts/regression.py)，覆盖项目→问题→协议→审计→Judge→指标→报告/CSV。
4. **P0C-04 项目列表过滤**：✅ 已实现，受限用户列表只返回被授权项目。
5. **P0C-05 报告访问审计**：✅ 已实现，查看/导出/下载写 `report.viewed`/`report.exported`/`report.downloaded`。

> P0C-01、P0C-03、P0C-04、P0C-05 已实现（2026-11-14）。P0C-02 部分完成：DeepSeek 真实链路通过；MiniMax 仍被账号配额（429/2056）阻塞。完成前不得启动 P0-S。

## 5. 支撑功能（P0-S）

核心门禁通过后按以下顺序开发，全部完成才可宣布 P0 发布：

| 顺序 | 功能 | 交付物 | 验收要点 |
|---:|---|---|---|
| S1 | FEAT-04 实体知识 | 实体抽取、Schema/JSON-LD 解析、关系、合并建议 | 实体有来源片段/置信度；低置信不自动合并 |
| S2 | FEAT-08 人工复核 | 复核队列、标注、一致性统计 | 抽样复核可追溯；Judge 版本可重算 |
| S3 | FEAT-10 内容质量 | Answer First、结构、证据 Findings | 规则可解释，进入报告“发现” |
| S4 | FEAT-01 完整权限 | 登录页、成员/邀请页、项目成员配置 | 权限在 UI 可见；最后 Owner 保护 |
| S5 | FEAT-12 收尾 | 逾期提示、通知消费 | 通知失败不回滚任务状态 |

## 6. 非核心功能（冻结池）

以下能力在 P0 发布前不排期：

- 持续监测（P1）：schedules/alerts/API/30s runner + SKIP LOCKED 领取 + 执行失败告警 + 双实例/故障演练完成
- 多站点/多区域品牌管理（P1）
- 外部来源采集、AI 爬虫日志分析（P1）
- 优化 Agent：草稿、Diff、发布、回滚（P3）
- 实验中心与统计验证（P2）
- 服务账号、API Token、SCIM/SSO 高级配置
- 任务附件、协作者、通知中心
- 自定义报告模板、分享链接、白标
- 高级分析：问题权重、竞品 Share of Voice（指标/报告章节/实体趋势/别名/正负语境）与问题级趋势完成

解冻条件：P0 发布门禁全部通过，且产品负责人书面确认下一阶段范围。
