## 实验按渠道隔离

修复一个会直接误导结论的缺陷：实验评估此前把 `model_api` 与 `consumer_app_capture` 的指标行一起求和，导致基线出现 3/4、处理 4/4 这种"看似有提升"的假象。

- `experiments` 新增 `channel` 字段（迁移 `000033_experiment_channel`），默认 `model_api`；
- 创建时校验渠道枚举，非法值返回 422；
- `metricCounts` 按 `dimensions.channel` 过滤后再计算分子分母。

实测：同一对审计在修复前后

| | 修复前 | 修复后 |
|---|---|---|
| baselineRate | 0.75 | 1.00 |
| treatmentRate | 1.00 | 1.00 |
| uplift | 0.25 | 0.00 |
| 结论 | insufficient_data | insufficient_data |

修复前 0.25 的"提升"完全来自把采集样本混入基线，属于统计口径错误。

## 配套：修复任务与交付物

- 依据 134 条 open finding，按规则归并生成 4 个优化任务（JS_ONLY / CANONICAL / AUTHOR+DATE / THIN），每个任务带验收项；
- 生成 3 份交付草稿：`jsonld`、`llms_txt`、`meta`；
- 建立实验骨架并绑定基线审计，treatment 待修复完成后绑定。

## 已知边界

- 实验仍只有前后对比，没有随机化/对照组；
- 一次评估只比较一个渠道，跨渠道结论需要分别建实验；
- 样本量现实约束：n=4 时最小可检测效应约 99 个百分点，等于测不出任何现实变化。
