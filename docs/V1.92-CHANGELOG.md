# GEO Intelligence P0 V1.92 增量记录

## 草稿发布写回（webhook 连接器）

补上"诊断 → 草稿 → 审批 → **发布**"的最后一段：审批通过的草稿可以真正推送到客户侧端点。

- 新增 `PUT /projects/{id}/publish-target`、`GET /projects/{id}/publish-target`：
  - 仅接受公开 http(s) 端点，loopback / 私有 / link-local 一律 422 `PUBLISH_TARGET_INVALID`；
  - 每个项目一个目标，重复配置覆盖。
- 新增 `POST /projects/{id}/content-drafts/{draftId}/publish`：
  - 只有 `approved` 的草稿可发布，否则 409 `DRAFT_NOT_APPROVED`；
  - 推送 `{event,projectId,draftId,kind,title,version,content,publishedAt}`；
  - 请求头 `X-Geo-Event: publish` 与 `X-Geo-Signature: sha256=<hmac>`（HMAC-SHA256，密钥来自 `GEO_PUBLISH_SECRET` 环境变量，不入库）；
  - 2xx 记为 `delivered` 并把草稿置为 `published`；非 2xx 记 `failed` 并返回 502。
- 新增 `POST /projects/{id}/publish-events/{eventId}/rollback`：对已投递的发布发送 `event=rollback`（含原因）。
- 新增 `GET /projects/{id}/publish-events`：交付审计（动作、状态、HTTP 码、错误码、响应摘要）。
- 迁移 `000032_publish_writeback` 增 `publish_targets` / `publish_events`。

## 实测

| 场景 | 结果 |
|---|---|
| 配置 `https://postman-echo.com/post` | 200 |
| `ftp://` 端点 | 422 `PUBLISH_TARGET_INVALID` |
| `http://127.0.0.1:9000/hook` | 422（私有地址拦截） |
| 发布已审批草稿 | 200，`delivered`，对端 200 |
| 草稿状态 | `published`，version=3 |
| 事件列表 | 1 条 |
| 回滚已投递事件 | 200，`delivered`，action=rollback |
| 发布未审批草稿 | 409 `DRAFT_NOT_APPROVED` |
| 证据 | `.run/publish-writeback-verification.json` |

## 测试

- HMAC 签名：确定性、密钥不同则签名不同、`sha256=` 前缀；
- 载荷构造：必需字段齐全、空 reason 省略、回滚带 reason；
- 端点校验：https 通过，`ftp://`、无 scheme、空串拒绝。

## 已知边界

- 密钥来自环境变量而非 KMS，多租户共用一个签名密钥；生产应改为按租户的 KMS 引用。
- 只支持 webhook 一种连接器，未接 CMS/Git PR。
- 回滚是"通知对端回退"，系统内不保存上一版正文快照。
- 发布失败不自动重试，需人工再次触发。
- 事件表保留 100 条查询上限，未做归档。
