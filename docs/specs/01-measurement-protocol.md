# SPEC-01：GEO 测量协议与指标口径

> 版本：V1.0｜状态：已批准｜适用范围：P0 GEO Audit

## 1. 目标与原则

本协议用于保证不同项目、批次和时间点的结果可解释、可复现、可比较。测量对象是“指定条件下采集到的 AI 回答”，不是第三方平台不可观察的内部排名。

原则：固定协议、分渠道统计、保存原始证据、重复采样、显式不确定性、禁止选择性报告。

## 2. 测量单元

一次采样单元定义为：

`问题版本 × 引擎 × 模型 × 渠道 × 地区 × 语言 × 参数配置 × 采样序号`

每个单元必须具有唯一 `sample_key`，相同键重试不得重复计费或重复计入指标。

### 2.1 渠道

| 类型 | 定义 | 汇总规则 |
|---|---|---|
| `model_api` | 通用模型 API | 仅在同类 API 内比较 |
| `search_api` | 正式搜索/带检索 API | 与具体 API 产品绑定 |
| `consumer_app_capture` | 经授权采集的消费者应用结果 | 按应用、账户条件分别报告 |

不同渠道禁止合并成一个总体可见度。报告标题和导出必须显示渠道。

## 3. 测量协议对象

`measurement_protocol` 至少包含：

- `protocol_version`：不可变语义版本。
- `question_set_version`：问题集快照。
- 引擎、模型及模型别名解析结果。
- 渠道、地区、语言、时区。
- Prompt 模板、系统消息及参数哈希。
- 每单元计划采样次数与最大重试次数。
- 有效回答规则版本、Judge 版本和指标版本。
- 调度窗口、预算上限和停止规则。

协议发布后不可修改；变化必须创建新版本。仅修正文案且不影响语义时可增加补丁版本。

## 4. 问题集治理

### 4.1 问题属性

每个问题包含原文、语言、主题、意图、漏斗阶段、目标受众、目标实体、业务价值、来源、状态和权重。状态为：

`draft → reviewed → benchmark → monitoring → retired`

### 4.2 问题分层

- 品牌型：明确包含品牌名，只用于品牌理解质量，不计入非品牌发现指标。
- 类目型：询问某类产品或服务。
- 比较型：要求比较多个方案。
- 场景型：从行业、角色或任务出发。
- 决策型：价格、部署、安全、采购和风险。

报告默认分层展示，禁止用大量品牌型问题抬高总体指标。

### 4.3 版本与冻结

审计启动时冻结问题文本和属性。问题修改只影响新版本。被淘汰问题保留历史数据，但不进入新的监测批次。

## 5. 采样流程

1. 校验协议、预算和供应商可用性。
2. 为全部采样单元生成确定性 `sample_key`。
3. 随机化调用顺序，减少时间窗口偏差。
4. 在协议指定窗口内执行并保存原始响应。
5. 对技术失败按状态机重试；内容性拒答不得伪装成技术失败重试。
6. 运行有效性判定和 Answer Judge。
7. 对低置信或抽样记录人工复核。
8. 达到完整性门槛后计算指标并发布报告。

默认每单元最少 3 次采样；正式趋势监测建议 10 次以上。具体数量由先导实验的方差和成本决定。

## 6. 回答状态与指标资格

回答状态拆为四个正交字段，禁止把传输状态、内容质量和回答语义混在同一个枚举中：

| 字段 | 枚举 | 说明 |
|---|---|---|
| `transport_status` | `succeeded`、`failed`、`timeout`、`cancelled`、`outcome_unknown` | 外部请求是否取得确定结果 |
| `content_validity` | `valid`、`empty`、`truncated`、`wrong_language`、`policy_blocked`、`unparseable` | 返回内容能否可靠分析 |
| `answer_outcome` | `answered`、`refusal`、`no_recommendation`、`recommendation`、`unknown` | 有效内容表达的回答结果 |
| `eligible_for_core_metrics` | boolean | 由版本化资格规则计算，不由模型自由决定 |

默认资格规则为 `transport_status=succeeded AND content_validity=valid`。因此拒答和没有推荐的正常回答默认进入核心指标分母，但分别通过 `answer_outcome` 展示；报告同时提供排除拒答的敏感性分析。任何规则变化必须创建新的 `eligibility_rule_version`。

## 7. 核心指标

设切片内 `eligible_for_core_metrics=true` 的回答集合为 `R`：

```text
Mention Rate = 含目标品牌提及的回答数 / |R|
Recommendation Rate = 主动推荐目标品牌的回答数 / |R|
Official Citation Rate = 引用目标品牌自有域名的回答数 / |R|
Trusted Third-party Citation Rate = 引用可信第三方且与品牌相关的回答数 / |R|
Positive Mention Rate = 正向提及回答数 / 含目标品牌提及的回答数
Eligible Response Rate = 指标合格回答数 / 计划采样数
Refusal Rate = answer_outcome=refusal 的合格回答数 / 指标合格回答数
```

同一回答多次提及在回答率中计一次；提及次数另存为 `mention_frequency`。分母为零时返回 `null`，不得返回 0%。

## 8. 聚合规则

- 回答等权：每条有效回答权重相同，适合反映实际采样结果。
- 问题等权：先计算每个问题指标，再对问题平均，避免采样不均。
- 业务加权：仅允许使用审计前冻结的问题权重，并同时展示未加权结果。
- 最小切片：少于 30 个有效回答时显示“小样本”警告；少于 5 个时不生成趋势结论。

不得跨渠道、跨不兼容协议或跨无法确认的模型版本直接聚合。

## 9. 不确定性与显著性

- 回答等权的简单二项比例使用 95% Wilson 置信区间。
- 问题等权使用以问题为聚类单位的 Cluster Bootstrap 区间。
- 业务加权使用冻结问题权重的加权 Cluster Bootstrap 区间。
- Bootstrap 默认使用确定性随机种子和不少于 2,000 次重采样，并保存算法版本、种子和重采样次数。
- 两批比例比较优先报告绝对差、相对差及区间。
- 同一问题重复测量采用配对分析；独立样本不得伪装为配对。
- 多问题、多指标同时检验时使用 Benjamini-Hochberg 控制 FDR。
- 除统计显著性外，必须设置业务最小效应阈值 MDE。

## 10. 数据完整性门槛

报告可发布条件：计划采样完成率不低于 90%，每个核心切片有效回答率不低于 80%，协议和 Judge 版本完整，成本记录完整。未达门槛时可生成“部分报告”，但必须显示缺失范围，不得进入正式趋势线。

## 11. 可比性矩阵

| 变化 | 默认是否可直接比较 | 处理方式 |
|---|---|---|
| 同协议、同问题集、同模型解析版本 | 是 | 正常趋势 |
| 问题文本变化 | 否 | 新问题版本，标记断点 |
| 模型供应商升级且版本可见 | 条件允许 | 分层并做桥接批次 |
| 模型版本未知 | 否 | 标记潜在断点，避免因果结论 |
| Judge 更新 | 可重算后比较 | 对两期原始响应使用同一 Judge 重算 |
| 地区、语言或渠道变化 | 否 | 独立序列 |

## 12. 报告最低披露

每份报告必须显示数据窗口、问题数、计划/成功/有效样本数、渠道、引擎、模型、地区、语言、协议版本、Judge 版本、指标版本、置信区间、异常和已知限制。

## 13. 验收标准

- 固定输入可从原始响应重算出相同分子、分母和指标。
- 分母为零、重复响应、部分失败和拒答均有自动化测试。
- 任一指标可下钻至构成它的回答及判定证据。
- 不兼容协议默认无法在 UI 中绘制连续趋势。
