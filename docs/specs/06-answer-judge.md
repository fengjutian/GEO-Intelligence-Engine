# SPEC-06：Answer Judge 标注与评估规范

> 版本：V1.0｜状态：研发评审稿｜对象：AI 回答有效性、提及、推荐、情感与引用

## 1. 目标

建立可重复的人工标注和机器评估体系，使核心指标具有可解释的质量基线。Judge 输出是带置信度和证据的结构化判断，不是无依据的单一分数。

## 2. 标注单元与输入

基本单元是一条完整原始回答及其问题、目标品牌档案、品牌别名、竞品表、渠道和引用元数据。标注者默认看不到实验组别和历史指标，减少期望偏差。

## 3. 标签体系

### 3.1 回答有效性

单选：`valid`、`refusal`、`no_recommendation`、`empty`、`transport_error`、`truncated`、`wrong_language`、`policy_blocked`。技术状态优先来自采集元数据，标注者只确认内容状态。

### 3.2 提及

每个提及标注字符起止位置、匹配文本、实体 ID 和类型：

- `direct_brand`：品牌正式名或别名。
- `product_implied`：产品唯一指向目标品牌。
- `ambiguous`：同名或上下文不足。
- `competitor`：竞品提及。

只有 `direct_brand` 和人工确认的 `product_implied` 进入目标品牌 Mention Rate。

### 3.3 推荐

回答级多标签：

- `primary_recommendation`：明确首选。
- `recommended_option`：正向列为合适候选。
- `conditional_recommendation`：仅在明确条件下适合。
- `neutral_listing`：仅列举，无建议语义。
- `not_recommended`：明确不建议或不适合。
- `insufficient`：无法判断。

Recommendation Rate 计入前三类；条件推荐单独可筛选。记录推荐顺序、列表位置和支持理由片段。

### 3.4 情感/立场

`positive`、`neutral`、`negative`、`mixed`、`unknown`。情感针对目标品牌在当前问题语境中的表达，不是整篇语气。必须选取支持片段。

### 3.5 引用

每条引用标注原始 URL、规范 URL、来源类别、是否与目标品牌相关，以及引用是否支持邻近主张：`supports`、`partially_supports`、`does_not_support`、`unknown`。

## 4. 边界案例

- “A、B、C 都是常见工具”属于 neutral listing，不是推荐。
- “如果需要私有化可考虑 A”属于 conditional recommendation。
- 品牌只出现在引用域名、正文未谈及品牌：计 Citation，不自动计 Mention。
- 回答引用官网但描述明显负面：Citation 与 Negative Mention 可同时成立。
- 产品名可能属于多个厂商且上下文不足：ambiguous，不计目标品牌。
- 模型拒答但在拒答中提到品牌：有效性为 refusal；提及可记录，核心指标是否计入由测量协议决定。

## 5. 标注流程

1. 标注负责人冻结指南版本和样本清单。
2. 标注者完成培训和资格测试，准确率达到 85% 才进入正式任务。
3. 核心 Benchmark 100% 双人独立标注；日常质检至少 20% 双标。
4. 分歧由资深仲裁员处理，保留原始标注和仲裁理由。
5. 每批计算一致性；低于门槛时暂停发布并复训。

一致性指标：分类使用 Cohen's Kappa/加权 Kappa，span 使用实体级 F1，引用 URL 使用规范化后精确匹配。

## 6. 黄金测试集

首版至少 500 条回答，覆盖中英文、不同渠道、目标品牌/竞品、拒答、长列表、否定、条件推荐、同名实体、引用缺失和错误引用。任何单一品牌、模型或类别不得超过 20%。

数据划分按问题和品牌分组，避免同一问题改写泄漏到训练与测试两侧：训练 60%、验证 20%、锁定测试 20%。锁定测试集仅由质量负责人访问。

## 7. Judge 流水线

```text
技术元数据校验
  → 回答有效性规则
  → 确定性实体/URL 候选
  → 上下文消歧与推荐/情感分类
  → 置信度校准
  → 低置信人工复核
  → 版本化结果
```

规则适合 URL、精确别名和技术状态；模型适合上下文消歧和语义分类。LLM 输出必须符合 JSON Schema，失败不得静默使用猜测结果。

## 8. 质量指标与发布门槛

| 能力 | 指标 | P0 门槛 |
|---|---|---|
| 品牌 Mention | 实体级 Precision/Recall/F1 | F1 ≥ 0.95，Precision ≥ 0.97 |
| Recommendation | Macro F1 | ≥ 0.85 |
| Citation URL | Precision/Recall/F1 | F1 ≥ 0.95 |
| 来源类别 | Macro F1 | ≥ 0.90 |
| Sentiment | Macro F1 | ≥ 0.80 |
| 有效回答 | Macro F1 | ≥ 0.95 |

同时按语言、模型、回答长度和问题类型分层报告；总体达标但关键分层低于总体 10 个百分点时不得无提示上线。

## 9. 置信度与人工复核

置信度必须用验证集做校准（如 isotonic/Platt 或分桶校准），不能直接把 LLM 自报概率当作可信概率。

以下进入复核：置信度低于阈值、规则与模型冲突、同名实体、混合情感、首选推荐不明确、引用支持性未知，以及随机 5% 质量抽样。

人工纠错生成独立记录，不直接覆盖机器结果；经审核后可加入下一版训练集。

## 10. 版本管理

Judge 版本包含代码、规则、Prompt、模型、别名快照、标签指南和配置哈希。任何影响输出的变化都创建新版本。版本发布前必须运行锁定测试集和与上一版本的差异分析。

历史原始响应可以批量重评估；报告必须绑定具体 Judge 版本。新版本不得自动替换已发布报告。

## 11. 漂移监控

每周/每批监控标签分布、低置信率、人工推翻率、回答长度、语言和模型变化。人工推翻率超过基线 5 个百分点、某类分布变化超过预设阈值或供应商模型升级时触发专项复评。

## 12. 标注安全与隐私

标注界面按项目授权；敏感数据默认脱敏；禁止下载全量原始回答。外包标注必须使用隔离环境、最小字段和合同约束。所有查看、导出和修改进入审计日志。

## 13. 验收

- 黄金测试集有版本、来源许可、标签分布和仲裁记录。
- 任一 Judge 结果能展示规则/模型版本、证据和置信度。
- CI 在 Judge 变更时自动运行回归并阻止低于门槛的版本发布。
- 人工纠错不会覆盖或破坏历史机器判定。
