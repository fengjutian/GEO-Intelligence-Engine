# SPEC-08：多租户安全与数据权限设计

> 版本：V1.0｜状态：已批准｜安全模型：共享应用、共享库、行级租户隔离

## 1. 安全目标

保护租户数据机密性、完整性和可用性；阻止跨租户访问、凭据泄漏、SSRF、提示注入和未经批准的生产变更。安全控制覆盖 API、数据库、缓存、队列、对象存储、日志、导出和备份。

## 2. 信任边界

不可信输入包括用户输入、网页内容、模型输出、Webhook、上传文件和第三方 API 响应。Crawler、模型适配器和内容处理 Worker 均按可能被恶意输入控制设计。

```text
Internet/User ─[WAF/Auth]─ API ─[Service Auth]─ Data Plane
Public Web ─[Isolated Egress]─ Crawler
Model Providers ─[Adapter Validation]─ Gateway
```

## 3. 身份认证

- 人类用户：OIDC/安全会话，密码场景使用强哈希；企业版支持 SSO。
- MFA：组织所有者、审批人和密钥管理员强制启用。
- 服务身份：短期工作负载凭据，禁止共享长期静态密钥。
- API Token：仅保存哈希，显示一次，带作用域、过期时间和最近使用时间。
- 会话：HttpOnly、Secure、SameSite，轮换刷新令牌，支持全局撤销。

## 4. 授权模型

采用 RBAC + 资源归属校验：

| 角色 | 主要能力 |
|---|---|
| Owner | 组织、账单、成员、全部项目 |
| ProjectAdmin | 指定项目配置、运行、导出、审批 |
| Analyst | 运行审计、编辑分析、创建任务 |
| Editor | 处理内容任务，不管理密钥和成员 |
| Approver | 审核变更，无权修改原始证据 |
| Viewer | 只读，导出能力可单独关闭 |
| ServiceAccount | 显式 scopes 和项目范围 |

授权函数输入必须包含主体、租户、动作、资源和上下文。前端隐藏按钮不是安全控制；每个 API 和异步任务执行时重新授权。

## 5. 租户隔离实现

### 5.1 数据库

- 请求上下文强制绑定一个 `tenant_id`，禁止客户端任意覆盖。
- Repository API 必须以 TenantContext 为必填参数。
- 查询使用 `(tenant_id, id)`，禁止只按全局 ID 更新业务记录。
- 关联表通过复合外键或事务校验阻止跨租户关联。
- 管理员跨租户工具独立部署、强审计、默认无权限。

### 5.2 Redis、队列与缓存

Key 统一前缀 `env:tenant:{tenant_id}:...`；消息体携带租户，消费者从数据库复核资源归属。缓存命中后仍执行授权，不缓存最终“允许”结果超过短 TTL。

### 5.3 对象存储

对象键包含租户和项目；服务端基于数据库归属签发 5 分钟以内的 URL。Bucket 不公开，禁止可枚举路径。租户级加密上下文防止错误解密。

### 5.4 日志和分析

日志平台按岗位授权；不记录正文、Prompt、响应和密钥。产品分析事件使用内部 ID，不发送客户内容给未经批准的第三方分析服务。

## 6. 密钥管理

- 供应商密钥、Webhook Secret 和 GitHub 凭据进入 KMS/Secret Manager。
- 数据库只存 `credential_ref` 和非敏感元数据。
- 密钥按租户和用途隔离，可轮换、撤销和追踪使用。
- UI 永不回显完整密钥；测试连接不在错误信息中返回供应商原始认证 Header。

## 7. 数据保护

- 外部与内部传输 TLS；数据库、对象存储和备份静态加密。
- 高敏字段采用应用层信封加密。
- 导出文件带短时下载链接、访问日志和过期清理。
- 生产数据禁止复制到开发环境；测试使用合成或脱敏数据。
- 数据分类：公开、内部、机密、受限；原始模型响应和客户网页快照默认机密。

## 8. Crawler 与 SSRF

Crawler 单独网络隔离，拒绝内网、loopback、链路本地、元数据地址和非授权端口；DNS 解析和每跳重定向均校验。无权访问主数据库、密钥管理和管理 API。详见 SPEC-04。

## 9. 提示注入与 Agent 安全

- 网页和模型输出始终作为不可信数据封装，不可变成系统指令。
- 内容分析 Worker 无发布、密钥和组织管理权限。
- 工具输入使用 JSON Schema 和允许列表，不允许模型拼接任意 Shell/URL。
- 生成与执行身份分离；P0 不提供自动发布能力。
- 未来高风险操作需要明确 Diff、人工批准和短时授权。

## 10. Web/API 安全

- 输入大小、类型和 JSON 深度限制；输出统一转义。
- 防 SQL 注入、XSS、CSRF、开放重定向、路径穿越和不安全文件解析。
- 登录、密钥、导出和报告分享接口独立限流。
- CORS 采用明确源列表；安全 Header 包括 CSP、HSTS、frame-ancestors 等。
- 错误响应不泄漏堆栈、SQL、文件路径、密钥或其他租户存在性。

## 11. 审计日志

记录登录、失败认证、成员和角色变化、密钥操作、审计启动/取消、原始数据查看、导出、报告分享、删除、审批和管理员访问。

事件包含主体、动作、资源、租户、结果、时间、IP/设备摘要、trace 和变更前后摘要。采用追加写和完整性保护；业务管理员不能删除。

## 12. 数据生命周期与隐私

- 项目配置保留策略，默认原始证据 365 天。
- 支持访问、导出、更正和删除请求，并记录完成证明。
- 删除覆盖主库、对象、缓存、索引和后续备份到期流程。
- 对外部网页中的 PII 做最小化、脱敏和访问限制。
- 跨境和第三方模型处理必须记录区域、子处理商及客户配置。

## 13. 威胁模型摘要

| 威胁 | 主要控制 |
|---|---|
| IDOR/跨租户访问 | TenantContext、复合查询、授权测试 |
| 缓存串租 | 租户键、授权后读取、自动测试 |
| 对象 URL 泄漏 | 私有 Bucket、短期签名、不可枚举键 |
| SSRF | 网络隔离、地址/端口/重定向校验 |
| Prompt Injection | 数据/指令分离、工具白名单、最小权限 |
| 密钥泄漏 | Secret Manager、脱敏、轮换和审计 |
| 恶意导出 | 权限、速率、短链、访问记录 |
| Worker 越权 | 独立身份、资源范围和服务认证 |

## 14. 安全验证门槛

- 跨租户 API、队列、缓存和对象存储测试 100% 通过。
- 依赖、容器和 IaC 扫描无未豁免 Critical/High。
- SSRF、XSS、SQLi、CSRF、IDOR 和权限提升测试通过。
- 生产密钥扫描无命中，日志抽检无敏感内容。
- 威胁模型和事件响应演练在 P0 发布前完成。

## 15. 事件响应

建立发现、分级、遏制、取证、清除、恢复和复盘流程。疑似跨租户泄漏为最高等级：立即冻结相关访问、保护日志、轮换凭据、评估通知义务。任何人不得为“快速恢复”删除证据。
