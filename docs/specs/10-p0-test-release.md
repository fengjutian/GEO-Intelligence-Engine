# SPEC-10：P0 测试计划与发布清单

> 版本：V1.0｜状态：研发评审稿｜发布对象：P0 GEO Audit

## 1. 测试目标

验证 P0 能够安全、准确、可恢复地完成“项目配置 → 网站抓取 → 问题集 → 多模型采样 → Judge → 指标 → 报告 → 优化任务”闭环，并达到 PRD 的发布门槛。

## 2. 质量责任

| 角色 | 责任 |
|---|---|
| 产品负责人 | 需求和指标口径验收、限制披露 |
| 技术负责人 | 架构、迁移、可靠性和发布决策 |
| QA 负责人 | 测试策略、证据、缺陷风险汇总 |
| 安全负责人 | 威胁模型、漏洞和隔离验收 |
| 数据/算法负责人 | Benchmark、Judge 和统计质量 |
| SRE/运维 | 容量、监控、备份、回滚和演练 |

发布采用 Go/No-Go 会议，任何 Must 门禁失败默认为 No-Go；豁免需要负责人、风险、到期日和补救措施。

## 3. 测试环境与数据

- `local`：单元与开发调试。
- `ci`：隔离数据库、模拟对象存储和供应商 Fixture。
- `staging`：与生产同拓扑和安全策略，使用合成/许可数据。
- `production canary`：内部租户和低配额真实调用。

禁止把生产客户数据复制到 CI/Staging。真实供应商测试使用独立低权限凭据和硬预算。

## 4. 测试层次

### 4.1 单元测试

覆盖 URL 规范化、robots、指标分子分母、Wilson 区间、状态转换、权限策略、成本整数计算、错误映射、Judge 规则和删除范围。核心纯函数行/分支覆盖率目标 ≥ 90%，普通业务模块 ≥ 80%；覆盖率不替代行为验收。

### 4.2 契约测试

- API OpenAPI 请求、响应和稳定错误码。
- Model Provider 适配器成功、失败、限流、超时和版本不透明。
- 对象存储读写、哈希和权限。
- Outbox/Inbox 事件 Schema 向后兼容。
- 数据库迁移前后版本兼容。

### 4.3 集成测试

使用真实 MySQL、Redis、S3 兼容存储和 Playwright，验证事务、队列、租约、对象写入、重评估和报告生成。第三方模型默认使用脱敏录制 Fixture。

### 4.4 端到端测试

至少覆盖：

1. 创建租户、项目、品牌和站点。
2. 完成域名授权并执行静态/动态抓取。
3. 确认实体并发布问题集。
4. 估算预算并启动双供应商审计。
5. 注入部分失败并恢复。
6. 查看四类指标、区间和证据下钻。
7. 导出 PDF/CSV 并创建优化任务。
8. 用新 Judge 版本重评估，旧报告保持不变。
9. 删除项目并验证数据清除流程。

## 5. 功能验收矩阵

| 范围 | 必测内容 | 通过标准 |
|---|---|---|
| 项目/RBAC | 角色、项目范围、归档 | 非授权操作全部拒绝且有审计 |
| 抓取 | robots、sitemap、JS、限额、取消 | 输出可追溯，无越界抓取 |
| 实体 | 抽取、消歧、人工确认 | 人工结论不被自动覆盖 |
| 问题集 | 版本、冻结、聚类 | 历史审计不受编辑影响 |
| Gateway | 幂等、预算、限流、重试 | 无重复计费业务记录 |
| Judge | 标签、证据、版本、复核 | 达到 SPEC-06 分层门槛 |
| 指标 | 口径、区间、切片、空分母 | 与独立重算一致 |
| 报告 | 披露、下钻、导出 | 每个结论可回到原始证据 |
| 任务 | 状态机、非法转换 | 非法转换拒绝并记录 |

## 6. 数据质量测试

- 审计计划数 = 各状态 sample 数之和。
- 有效分母与有效性规则一致。
- Mention/Recommendation/Citation 分子可由 evaluation 明细重建。
- 指标 `0 ≤ numerator ≤ denominator`，空分母 value 为 null。
- 所有派生记录具有输入、算法和配置版本。
- 原始对象引用存在且 SHA-256 一致。
- 跨项目实体、问题、响应和报告关系被约束阻止。

每日运行数据一致性巡检；发现严重不一致时冻结报告发布。

## 7. Judge 与 Benchmark 测试

- 锁定测试集执行结果满足 SPEC-06 门槛。
- 报告总体和中文/英文、长/短回答、不同模型分层结果。
- 新版本与上一版本差异抽样复核。
- 低置信进入复核队列，人工纠错保留双版本。
- Benchmark 给出自然方差、成本和推荐采样次数。

## 8. 安全测试

### 8.1 多租户

对每个资源 API 执行 A 租户读取/更新/删除 B 租户 ID；覆盖列表筛选、批量接口、导出、签名 URL、缓存、队列和 WebSocket/通知。预期统一拒绝且不泄漏资源是否存在。

### 8.2 抓取安全

测试 IPv4/IPv6 loopback、十进制/八进制编码、DNS Rebinding、跨跳重定向、云元数据、私网端口、超大响应、压缩炸弹和恶意 HTML。预期全部阻断或受限。

### 8.3 应用安全

执行 SAST、SCA、Secret Scan、容器/IaC 扫描和 DAST；手工覆盖 IDOR、SQLi、XSS、CSRF、权限提升、会话固定、开放重定向和导出滥用。

### 8.4 Prompt Injection

恶意网页和模型回答尝试读取密钥、改变系统指令、访问内网或触发发布。P0 内容处理服务必须无相关权限，工具输入应拒绝越界参数。

## 9. 可靠性与故障注入

在每个持久化点杀死 Worker；注入 MySQL、Redis、S3、DNS、Playwright 和供应商短暂故障；验证重试、熔断、租约回收、部分成功和死信。

关键场景：供应商已成功但本地超时、对象已写但事务失败、Outbox 重复投递 100 次、报告生成中断、取消与完成竞争、预算结算失败。

通过标准：不丢失已确认数据，不重复业务结果，不越过预算硬上限，恢复路径有审计。

## 10. 性能与容量

### 10.1 基线场景

- 100 并发交互用户。
- 10 个并发审计。
- 单项目 10,000 页面、1,000 问题、20,000 响应。
- 100 万回答历史数据下的报告查询。

### 10.2 门槛

- 常规 API P95 ≤ 500ms，错误率 < 1%。
- 常规报告查询 P95 ≤ 2s，大导出异步。
- 队列扩容后积压趋于收敛，无租户饥饿。
- 预算、限流和数据库连接池在峰值下保持有效。

性能测试不调用无限制真实供应商；使用可控延迟和错误分布的模拟器。

## 11. 可访问性与兼容性

- 关键流程键盘可完成，焦点可见，表单有标签和错误说明。
- 色彩、表格和图表达到 WCAG 2.1 AA 目标；图表提供文本/表格替代。
- 支持当前及前一主版本 Chrome、Edge、Safari；移动端至少可查看报告。
- 中文、英文、长品牌名、RTL 内容作为输入不破坏布局，P0 UI 可暂不支持完整 RTL。

## 12. 备份、恢复和删除演练

- 从备份恢复到隔离环境，验证业务行、对象引用和指标一致性。
- 证明 RPO ≤ 24h、RTO ≤ 4h。
- 删除一个测试租户，核查数据库、对象、缓存、索引、报告和后续备份到期标记。
- 恢复和删除结果由非执行人复核。

## 13. 可观测性验收

确认关键 Dashboard、告警路由和 Runbook：API 错误、队列老化、供应商故障、费用异常、抓取阻断、Judge 漂移、报告不一致、备份失败和安全事件。随机选择报告结论可用 trace 追到原始响应。

## 14. 发布门禁

### 14.1 Must

- PRD 所有 P0 Must 需求通过并有证据。
- 核心 E2E 成功率 ≥ 95%，无阻断缺陷。
- Mention F1 ≥ 0.95 且 Precision ≥ 0.97；Recommendation Macro F1 ≥ 0.85；Citation URL F1 ≥ 0.95；来源分类 Macro F1 ≥ 0.90；Sentiment Macro F1 ≥ 0.80；有效性 Macro F1 ≥ 0.95，或启用经产品、算法和 QA 共同批准的人工降级。
- 跨租户、SSRF、权限和密钥测试 100% 通过。
- 无未豁免 Critical/High 安全漏洞。
- 指标从原始数据独立重算一致。
- Worker 故障恢复、预算熔断和幂等测试通过。
- 备份恢复、回滚和事件响应演练完成。
- 监控、告警、值班和 Runbook 就绪。
- 用户文档披露渠道、样本、限制和不保证推荐。

### 14.2 Should

- 中低风险缺陷有明确优先级和目标版本。
- 容量达到预计首月峰值 2 倍。
- Canary 连续运行 7 天无数据完整性和隔离问题。

## 15. 发布策略

1. 数据库采用向后兼容迁移并完成备份。
2. 内部租户 Canary。
3. 5% 试点租户，观察核心 SLI 和成本。
4. 25% → 50% → 100% 分阶段扩大，每阶段至少覆盖一个完整审计周期。
5. 每阶段由技术、QA、SRE 联合确认继续或回滚。

功能开关按租户控制新 Judge、供应商和报告模板。开关不是永久兼容层，稳定后清理。

## 16. 回滚条件和方案

立即停止扩大发布：跨租户风险、指标错误、不可恢复数据损坏、预算失控、Critical 安全问题、错误率/延迟持续超阈值。

回滚顺序：关闭功能开关/新任务 → 回滚应用 → 停止受影响 Worker → 执行前向数据修复。已执行数据库迁移默认不做破坏性 Down Migration；使用向后兼容 Schema 和前向修复。

## 17. 发布清单

### 产品与数据

- [ ] P0 范围和非目标已冻结。
- [ ] 指标口径、问题集和协议版本已批准。
- [ ] Benchmark 和 Judge 报告已签署。
- [ ] 报告限制与渠道说明清晰。

### 工程

- [ ] 代码评审、测试、迁移和契约检查通过。
- [ ] 幂等键、预算、限流和超时已配置。
- [ ] Feature Flag、Canary 和回滚路径验证。
- [ ] 第三方依赖和许可证清单完成。

### 安全与合规

- [ ] 威胁模型、安全测试和漏洞处置完成。
- [ ] Secret、权限和跨租户检查通过。
- [ ] 数据保留、删除、隐私和第三方处理说明批准。
- [ ] robots、版权和数据源许可完成评审。

### 运维

- [ ] Dashboard、告警、值班表和 Runbook 就绪。
- [ ] 备份恢复、故障注入和容量测试完成。
- [ ] 供应商配额、预算和账单告警启用。
- [ ] 状态页和客户支持升级路径准备完毕。

### 发布后

- [ ] 24 小时、72 小时和 7 天复盘已安排。
- [ ] 核对成本、有效回答率、Judge 低置信率和用户反馈。
- [ ] 所有临时豁免有责任人和到期日。

## 18. 发布证据包

Go/No-Go 会议必须具备：需求追踪矩阵、自动化测试报告、E2E 录像/日志、Judge 质量报告、Benchmark 报告、安全报告、性能报告、恢复演练记录、数据迁移计划、回滚 Runbook、已知问题和签署记录。
