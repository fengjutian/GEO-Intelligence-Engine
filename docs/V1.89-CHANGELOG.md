## SPEC-11 渠道采集协议 P1 落地

实现 [SPEC-11](../specs/11-channel-capture.md) 的人工控制台路径（C/D 级），不依赖任何第三方账号。

- 新增 `POST /api/v1/capture-batches`：
  - 报文含 `batchId`、`agent`、`captures`（原始字节保留用于验签）；
  - 必需 `X-Capture-Protocol: 1`，否则 400 `CAPTURE_PROTOCOL_UNSUPPORTED`；
  - 单批 1–100 条，逐条返回 `accepted` / `duplicate` / `rejected` + 错误码。
- 新增 `GET /api/v1/capture-batches/{batchId}`、`GET /api/v1/audits/{auditId}/captures`、`POST /api/v1/captures/{captureId}/revoke`。
- 存储映射（复用现有审计链路）：
  - `audit_samples`：按 `(audit, question, engine_config)` 递增 `sample_no`，`channel=consumer_app_capture|search_api`；
  - `ai_responses`：`request_id=NULL`（迁移 000030 放开 NOT NULL），`cost_microunits=0`，`raw_hash=sha256(answer)`；
  - 新增 `capture_provenance`：批次、trust tier、方法、观察时间、截图哈希、consent、签名状态、撤回时间。
- 校验：渠道（`model_api` 不可采集）、问题必须属于该审计的版本、时间 ±7 天、consent 必填、引用必须 http(s)。
- 可信度：`partner_api`/`browser_extension` 必须验签（ed25519，公钥来自 `GEO_CAPTURE_AGENT_KEYS`），未通过直接拒绝；`manual_console` 有截图哈希为 C 级，否则 D 级。
- 评估：入库后调用 Judge 并写 `answer_evaluations`，复用 `audits.RecordEvaluation`；评估失败不影响采集入库。

## 实测

| 场景 | 结果 |
|---|---|
| 人工采集（C 级） | `accepted`，tier=C，provider=openai，model=gpt-5 |
| 重复提交同一 capture | `duplicate`，库中仅 1 条 |
| `channel=model_api` | `rejected / CHANNEL_NOT_CAPTURABLE` |
| 扩展未签名 | `rejected / ATTESTATION_INVALID` |
| Judge 结果 | `recommendation` / `mentioned` / eligible=1 |
| 撤回 | 204，列表 `revoked=true` |
| 证据 | `.run/capture-protocol-verification.json` |

## 测试

- 校验：合法人工采集、`model_api` 拒绝、缺 consent、时间越界、空答案、非法引用；
- 可信度：A/B/C/D 映射与报告计入策略；
- 幂等键：同分钟稳定、跨分钟与改答案变化；
- 验签：ed25519 正确签名通过、篡改失败、无签名返回 false；
- 批量解码：空数组、非法 JSON、正常数组。

## 已知边界

- 未实现 `search_api`（AI Overviews）的独立抓取，只复用同一提交协议；
- 未做 OCR 管道与截图存储，只接收哈希；
- 采集答案进入指标需要 `POST /audits/{id}/metrics/recompute` 触发重算，暂未自动触发；
- `GET /capture-batches/{id}` 只返回已接受的 capture，不含被拒绝项的原始报文；
- 渠道白名单仍是自由文本 `surface.product`，未强制登记表。
